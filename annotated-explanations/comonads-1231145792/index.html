검토일: 2026-09-21

이 문서에서 설명하는 내용

Bartosz Milewski의 「Comonads」는 모나드의 화살표를 뒤집어 코모나드를 정의한 뒤, 이를 Haskell의 extract, duplicate, extend와 범주론의 코모노이드(comonoid)로 연결합니다. 하이라이트는 그중에서도 설명이 가장 압축된 두 지점을 짚습니다.

첫째는 duplicate와 extend가 어떻게 서로를 정의하는지 보여 주는 코드입니다. 둘째는 모노이드 범주의 왼쪽·오른쪽 유니터(unitor)와 bimap을 사용하여, 집합과 곱의 범주에서는 코모노이드의 split이 결국 x를 두 번 내놓는 함수일 수밖에 없음을 보이는 계산입니다.

별도의 사용자 메모가 없으므로 하이라이트의 의도를 하나로 단정할 수는 없습니다. 따라서 이 글에서는 두 부분을 이해하는 데 필요한 공통 개념을 먼저 세우고, 각 하이라이트에서 생략된 타입 계산과 등식 변형을 차례대로 풀어 설명합니다.

먼저 알아야 할 공통 개념

코모나드는 “초점이 있는 문맥”을 다룹니다

코모나드 w의 값을 w a라고 쓰면, 이를 단순히 a를 담은 상자로만 생각하기보다는 현재 초점과 그 주변 문맥을 함께 가진 구조로 보는 편이 이 글의 예제를 이해하기 좋습니다. 다만 이것은 Product, Stream, Store 같은 예제에 잘 맞는 교육적 직관이지, 모든 코모나드의 정의 자체는 아닙니다.

핵심 연산은 다음 세 가지입니다.

extract   :: w a -> a
duplicate :: w a -> w (w a)
extend    :: (w a -> b) -> w a -> w b
  • extract는 현재 초점에 있는 a를 꺼냅니다.
  • duplicate는 같은 문맥을 가능한 각 초점에서 바라본 w a들의 구조를 만듭니다.
  • extend f는 문맥 전체를 읽는 계산 f :: w a -> b를 각 초점에 적용하여 w b를 만듭니다.

예를 들어 원문의 무한 스트림에서는 첫 원소가 현재 초점입니다. 스트림을 개념적으로 10, 20, 30, …이라고 쓰면 duplicate의 결과는 다음처럼 각 위치에서 시작하는 스트림들의 스트림으로 볼 수 있습니다.

(10, 20, 30, …),
    (20, 30, …),
        (30, …),
            …

여기에 “현재 위치부터 두 값을 평균 내는 함수”를 extend하면 결과는 15, 25, …가 됩니다. 중요한 점은 그 함수가 원래의 원소 a 하나만 받는 것이 아니라, 각 위치에 초점을 맞춘 문맥 w a 전체를 받는다는 사실입니다.

현재 Control.Comonad 공식 문서는 최소 구현으로 extract와 함께 duplicate 또는 extend 중 하나를 요구합니다. 나머지 하나는 기본 정의로 얻을 수 있습니다. 그러나 타입이 맞는 것만으로 코모나드가 되지는 않으며, 다음과 같은 항등 법칙과 결합 법칙도 만족해야 합니다. 아래 목록은 duplicate를 기본 연산으로 삼아 적은 법칙입니다. extend를 기본 연산으로 구현할 때에는 공식 문서의 extend 법칙이 같은 역할을 하며, 두 연산을 모두 직접 구현하면 둘의 일관성 조건도 지켜야 합니다.

extract . duplicate = id
fmap extract . duplicate = id
duplicate . duplicate = fmap duplicate . duplicate

즉, duplicate는 실행 시 메모리를 복제한다는 뜻이 아닙니다. 코모나드의 구조 안에서 문맥과 초점을 재배치하는 연산이며, 위 법칙을 만족해야 한다는 뜻입니다.

함수 합성과 fmap은 타입을 이어 줍니다

Haskell에서 (f . g) x = f (g x)이므로 f . g는 표기상 오른쪽의 g를 적용한 결과를 f에 넘기는 합성입니다. Data.Function 공식 문서가 정의하는 이 합성 규칙에 따라, 두 함수를 합성하려면 앞 함수의 출력 타입과 뒤 함수의 입력 타입이 맞아야 합니다.

fmap은 펑터의 바깥 구조를 유지하면서 안쪽 값에 함수를 적용합니다.

fmap :: (x -> y) -> w x -> w y

따라서 f :: w a -> b라면 fmap f의 타입은 다음처럼 바뀝니다.

fmap f :: w (w a) -> w b

이 한 줄이 duplicate와 extend의 관계를 푸는 핵심입니다. duplicate가 먼저 w a를 w (w a)로 만들면, fmap f가 각 안쪽 문맥에 f를 적용할 수 있습니다.

모노이드 범주의 단위와 유니터

모노이드 범주(monoidal category)에는 두 대상을 결합하는 텐서곱 ⊗와 단위 대상 I가 있습니다. 단위 대상은 결합의 왼쪽이나 오른쪽에 놓여도 원래 대상을 바꾸지 않는 역할을 합니다. 이 “바뀌지 않음”은 보통 문자 그대로 같은 대상이라는 뜻이 아니라, 다음의 표준적인 동형사상으로 주어집니다.

λ_A :: I ⊗ A -> A
ρ_A :: A ⊗ I -> A

λ가 왼쪽 유니터이고 ρ가 오른쪽 유니터입니다. 유니터의 일반적인 정의와 일관성 조건은 MIT의 강의 자료인 Tensor Categories에서 확인할 수 있습니다.

원문이 계산하는 Set, 즉 집합과 전체 함수의 범주에서는 텐서곱을 데카르트 곱 ×로, 단위 대상을 원소가 하나뿐인 집합 1로 잡습니다. 이를 Haskell과 비슷하게 쓰면 1은 유닛 타입 ()에 해당하고, 유니터는 다음처럼 단위 성분을 제거합니다.

lambda :: ((), a) -> a
lambda ((), x) = x

rho :: (a, ()) -> a
rho (x, ()) = x

여기서 lambda는 범주론 기호 λ를 함수 이름처럼 적은 것입니다. Haskell에서 \x -> ...로 쓰는 람다 추상화와는 다른 말입니다.

코모노이드의 split, destroy, 두 counit 법칙

모노이드의 곱셈과 단위 화살표를 뒤집으면 코모노이드의 두 연산을 얻습니다.

split   :: m -> (m, m)
destroy :: m -> ()

destroy는 값을 단위 대상으로 보내고, split은 하나의 값을 두 성분으로 보냅니다. ()에는 전체 함수의 관점에서 가능한 결과가 하나뿐이므로 destroy _ = ()입니다.

임의의 split은 두 성분 함수를 사용하여 다음처럼 쓸 수 있습니다.

split x = (f x, g x)

코모노이드의 왼쪽·오른쪽 counit 법칙은 다음과 같습니다.

lambda . bimap destroy id . split = id
rho . bimap id destroy . split = id

여기서 bimap은 쌍의 두 성분에 서로 다른 함수를 적용합니다. 쌍에 대한 동작은 다음과 같습니다.

bimap p q (u, v) = (p u, q v)

이 동작은 Data.Bifunctor 공식 문서의 bimap 정의와 쌍의 Bifunctor 인스턴스에 해당합니다. 두 counit 법칙은 split한 뒤 한쪽을 버리고 단위 성분을 제거하면 원래 값이 그대로 돌아와야 한다는 뜻입니다.

하이라이트와 메모별 해설

duplicate와 extend는 어떻게 서로를 정의하나요?

하이라이트:

duplicate :: w a -> w (w a)
  duplicate = extend id
  extend :: (w a -> b) -> w a -> w b
  extend f = fmap f . duplicate

원문 문맥:

Here’s the Haskell definition taken directly from Control.Comonad library:

class Functor w => Comonad w where
  extract :: w a -> a
  duplicate :: w a -> w (w a)
  duplicate = extend id
  extend :: (w a -> b) -> w a -> w b
  extend f = fmap f . duplicate

첫 번째 등식 duplicate = extend id는 extend의 타입 변수 b에 w a를 대입하면 드러납니다.

extend    :: (w a -> b)   -> w a -> w b

b = w a

extend    :: (w a -> w a) -> w a -> w (w a)
id        ::  w a -> w a
extend id ::                 w a -> w (w a)

extend id의 최종 타입이 정확히 duplicate :: w a -> w (w a)와 같습니다. 의미 면에서도 id는 각 초점의 문맥 w a를 변형하지 않고 그대로 결과값으로 삼습니다. 그러므로 모든 초점에서 바라본 문맥들을 바깥의 w 안에 모은 결과가 됩니다.

두 번째 등식 extend f = fmap f . duplicate는 데이터가 흐르는 순서로 보면 더 분명합니다.

w a
  ── duplicate ──> w (w a)
  ── fmap f ─────> w b

각 함수의 타입은 다음과 같이 정확히 이어집니다.

duplicate :: w a     -> w (w a)
f         :: w a     -> b
fmap f    :: w (w a) -> w b

따라서 오른쪽부터 합성한 fmap f . duplicate의 타입은 w a -> w b가 되며, 이는 extend f가 요구하는 타입과 같습니다. 동작도 같은 흐름입니다. 먼저 duplicate가 가능한 초점별 문맥을 만들고, 이어서 fmap f가 각 문맥에 f를 적용합니다.

두 기본 정의가 서로를 가리킨다고 해서 아무 구현도 하지 않아도 된다는 뜻은 아닙니다. 실제 인스턴스는 extract를 구현하고 duplicate나 extend 중 적어도 하나에 생산적인 정의를 제공해야 합니다. 둘 다 기본 정의에 맡기면 서로를 계속 호출할 뿐 실제 결과를 만들지 못합니다. 또한 타입이 맞더라도 앞에서 본 코모나드 법칙을 만족해야 올바른 인스턴스입니다. 이 조건들은 Control.Comonad 공식 문서의 최소 구현과 법칙에 명시되어 있습니다.

왼쪽 유니터와 오른쪽 유니터는 무엇인가요?

하이라이트: the left and right unitors

원문 문맥:

lambda . bimap destroy id . split = id
rho . bimap id destroy . split = id

Here, lambda and rho are the left and right unitors, respectively (see the definition of monoidal categories).

유니터는 단위 대상을 텐서곱의 한쪽에서 제거하는 표준 동형사상입니다. 이 글의 구체적인 계산에서는 텐서곱이 쌍이고 단위 대상이 ()이므로, 왼쪽 유니터 lambda는 ((), x)에서 x를 꺼내고 오른쪽 유니터 rho는 (x, ())에서 x를 꺼냅니다.

lambda ((), x) = x
rho (x, ()) = x

따라서 첫 번째 counit 법칙의 합성은 다음 순서로 읽을 수 있습니다.

  1. split이 x를 두 성분으로 보냅니다.
  2. bimap destroy id가 왼쪽 성분을 ()로 버리고 오른쪽 성분은 그대로 둡니다.
  3. lambda가 남은 ((), 값)에서 단위 성분을 제거합니다.
  4. 전체 결과는 법칙에 따라 원래의 x, 즉 id x여야 합니다.

두 번째 법칙은 좌우가 반대입니다. 오른쪽 성분을 버린 뒤 rho로 단위 성분을 제거해도 원래의 x가 돌아와야 합니다. 그래서 두 법칙을 함께 적용하면 split의 어느 쪽 성분도 원래 값을 바꿀 수 없습니다.

bimap destroy id를 적용하면 왜 ((), g x)가 되나요?

하이라이트:

lambda (bimap destroy id (f x, g x))
= lambda ((), g x)

원문 문맥:

lambda (bimap destroy id (split x))
= lambda (bimap destroy id (f x, g x))
= lambda ((), g x)
= g x

원문은 bimap의 중간 계산을 한 번에 줄였습니다. 이를 성분별로 펼치면 다음과 같습니다.

bimap destroy id (f x, g x)
= (destroy (f x), id (g x))
= ((), g x)

첫 번째 성분에는 destroy가 적용됩니다. destroy는 어떤 값을 받아도 유닛 값 ()를 반환하므로 destroy (f x) = ()입니다. 두 번째 성분에는 항등함수 id가 적용되므로 id (g x) = g x입니다. 따라서 쌍 전체가 ((), g x)가 됩니다.

이제 왼쪽 유니터를 적용하면 단위 성분이 사라집니다.

lambda ((), g x) = g x

여기까지만 보면 계산 결과가 단지 g x라는 사실만 알 수 있습니다. g = id라는 결론은 이 계산이 원래 다음 counit 법칙의 왼쪽을 전개한 것이라는 데서 나옵니다.

lambda . bimap destroy id . split = id

임의의 x에 양변을 적용하면 왼쪽은 방금 본 계산에 따라 g x이고, 오른쪽은 id x = x입니다.

g x = x    모든 x에 대하여

함수의 외연적 동등성에 따라 모든 입력에서 결과가 같으므로 g = id입니다. 오른쪽 counit 법칙도 같은 방식으로 전개됩니다.

rho . bimap id destroy . split = id

이번에는 계산 결과가 f x가 되므로 모든 x에 대해 f x = x이고, 따라서 f = id입니다. 결국 임의적이었던 두 성분 함수가 모두 항등함수로 정해집니다.

split x = (f x, g x)
        = (x, x)

이 대각 함수와 유일한 destroy :: m -> ()는 Set의 데카르트 곱이 모든 대상에 제공하는 표준적인 가환 코모노이드 구조입니다. “자명한 코모노이드”라는 원문의 표현은 대상마다 별도의 복사·삭제 방식을 선택하는 것이 아니라 곱과 단위 대상의 구조가 두 연산을 정해 준다는 뜻으로 이해하는 편이 정확합니다. 데카르트 모노이드 범주가 이러한 표준 가환 코모노이드 구조를 제공한다는 설명은 Fong과 Spivak의 논문 “Supplying bells and whistles in symmetric monoidal categories”에서 확인할 수 있습니다.

이 계산은 집합과 전체 함수의 범주인 Set을 기준으로 합니다. 실제 Haskell에는 종료하지 않는 계산과 bottom 같은 의미론적 문제가 있으므로, 모든 Haskell 프로그램을 곧바로 Set의 전체 함수로 동일시하는 더 강한 결론까지 뜻하지는 않습니다.

두 하이라이트 묶음은 어떻게 연결되나요?

첫 번째 묶음의 extract와 duplicate는 각각 코모나드의 counit과 comultiplication에 해당합니다. 범주론적으로 코모나드는 함수자 합성을 텐서곱으로 삼는 자기함자(endofunctor)의 모노이드 범주 안에서 코모노이드입니다. 이 표준 정의는 Škoda의 논문 “Cyclic structures for simplicial objects from comonads”에서도 명시되어 있습니다.

extract   : 문맥에서 현재 초점을 꺼냅니다.
duplicate : 하나의 문맥을 초점별 문맥들의 구조로 펼칩니다.

두 번째 묶음은 같은 코모노이드 개념을 더 익숙한 데카르트 곱의 범주 Set에 적용한 별도의 예입니다.

destroy : 값을 단위 대상으로 보냅니다.
split   : 값을 두 곱 성분으로 보냅니다.

Set에서는 단위 대상으로 보내는 방법이 유일하고, counit 법칙 때문에 두 곱 성분이 모두 원래 값이어야 합니다. 그래서 split x = (x, x)가 됩니다. 반면 코모나드의 duplicate :: w a -> w (w a)는 일반적인 메모리 복사 연산이 아니라, 자기함자 w가 나타내는 문맥을 한 단계 더 중첩하는 comultiplication입니다. 두 연산은 모두 “코모노이드의 화살표”이지만 서로 다른 모노이드 범주에서 구체화되므로, duplicate를 단순히 Haskell 값의 물리적 복제로 해석하면 안 됩니다.

정리

duplicate = extend id는 extend의 결과 타입 b를 w a로 특수화하면 타입이 정확히 맞습니다. extend f = fmap f . duplicate는 duplicate로 초점별 문맥을 만든 뒤 fmap f로 각 문맥을 계산하는 합성입니다. 실제 코모나드 인스턴스에는 extract와 두 연산 중 하나의 구현뿐 아니라 코모나드 법칙도 필요합니다.

왼쪽·오른쪽 유니터는 단위 대상을 텐서곱의 왼쪽이나 오른쪽에서 제거합니다. Set의 데카르트 곱에서는 각각 ((), x)와 (x, ())를 x로 보냅니다. bimap destroy id (f x, g x)는 두 성분에 함수를 따로 적용하므로 ((), g x)가 되고, 왼쪽 counit 법칙은 여기서 g = id를 강제합니다. 오른쪽 법칙도 f = id를 강제하므로 최종적으로 split x = (x, x)가 됩니다.
