이 문서에서 설명하는 내용

원문은 짧은 인라인 <script>가 실행되는 자리에서 자기 자신을 계산 결과로 바꾸는 기법을 소개합니다. 하이라이트에는 별도 메모가 없으므로 선택 의도를 단정할 수는 없습니다. 다만 함수 정의의 앞부분만 선택했다는 점을 고려해, 그 안에 압축된 자바스크립트 문법과 전체 함수의 실행 흐름을 중심으로 설명합니다.

하이라이트와 메모별 해설

함수 정의의 압축 문법을 어떻게 읽나요?

하이라이트: $=(...n)=>

원문 문맥:

$=(...n)=>document.currentScript.replaceWith(...n)

원문 코드는 생략 가능한 공백이 없어 매우 압축되어 있습니다. 의미를 드러내도록 괄호와 공백을 추가하면 다음과 같이 읽을 수 있습니다. 아래 코드는 설명을 위해 다시 쓴 것이며 원문 인용이 아닙니다.

$ = (
  (...n) => document.currentScript.replaceWith(...n)
);

왼쪽부터 토큰별 의미는 다음과 같습니다.

  1. $는 함수에 붙인 짧은 이름입니다. 자바스크립트에서는 $ 하나만으로도 유효한 식별자가 되지만, $ 자체에 내장된 함수나 템플릿 의미는 없습니다. 작성자가 이 이름에 함수를 할당했기 때문에 함수처럼 동작합니다. 식별자에 사용할 수 있는 문자는 MDN의 자바스크립트 어휘 문법에서 확인할 수 있습니다.
  2. =는 오른쪽에서 생성되는 함수 객체를 $라는 이름이 가리키는 대상에 할당합니다.
  3. (...n)의 ...n은 나머지 매개변수(rest parameter)입니다. 호출할 때 받은 모든 인자를 n이라는 배열에 모읍니다. 나머지 매개변수는 매개변수 목록의 마지막에 있어야 하며, 화살표 함수에서 사용할 때는 이 예처럼 괄호가 필요합니다. MDN의 나머지 매개변수 설명이 이 규칙을 정리합니다.
  4. =>는 왼쪽의 매개변수를 받는 화살표 함수(arrow function)의 본문이 오른쪽에 이어진다는 표시입니다.

이 함수는 중괄호가 없는 표현식 본문을 사용하므로 오른쪽 표현식의 결과를 암시적으로 반환합니다. 다만 replaceWith()는 undefined를 반환하므로, 이 함수의 목적은 유용한 반환값을 만드는 것이 아니라 DOM을 변경하는 데 있습니다. 표현식 본문 규칙은 MDN의 화살표 함수 설명에, 반환값은 MDN의 Element.replaceWith() 설명에 나와 있습니다.

같은 ...n이 왜 두 번 나오나요?

같은 ... 토큰이 위치에 따라 반대 방향으로 작동합니다.

  • 매개변수 위치의 ...n은 여러 호출 인자를 배열 n으로 모읍니다.
  • 함수 호출 위치의 ...n은 배열 n의 원소를 여러 인자로 다시 펼칩니다.

예를 들어 다음과 같이 호출한다고 가정할 수 있습니다.

$("앞", "뒤")

먼저 나머지 매개변수가 두 인자를 배열로 모읍니다.

["앞", "뒤"]

그다음 함수 본문의 전개 구문이 배열 원소를 replaceWith()에 각각 전달합니다. 실행되는 호출은 개념적으로 다음과 같습니다.

document.currentScript.replaceWith("앞", "뒤")

나머지 매개변수는 여러 값을 배열 하나로 “모으고”, 호출 위치의 전개 구문은 이 배열을 여러 인자로 “펼칩니다”. 전개 구문은 일반적으로 이터러블(iterable)에 사용할 수 있지만, 이 예제에서 나머지 매개변수가 만드는 n은 배열입니다. 함수 호출에서의 전개 규칙은 MDN의 전개 구문 설명에서 확인할 수 있습니다.

현재의 <script>가 결과로 바뀌는 과정

페이지가 일반적인 비모듈 스크립트를 처음 처리하는 동안 document.currentScript는 현재 실행 중인 HTMLScriptElement를 가리킵니다. replaceWith()는 그 요소를 전달받은 노드나 문자열로 교체하며, 문자열은 HTML로 다시 해석되지 않고 텍스트 노드가 됩니다. 이 동작은 MDN의 Document.currentScript 설명, MDN의 Element.replaceWith() 설명, DOM 표준의 replaceWith() 정의에서 확인할 수 있습니다.

원문의 사용 예는 다음과 같습니다.

The year is <script>$(new Date().getFullYear())</script>

인라인 스크립트가 동기적으로 실행되는 순간에는 document.currentScript가 바로 이 <script> 요소를 가리킵니다. new Date().getFullYear()가 반환한 연도가 $의 인자로 들어가고, 함수는 스크립트 요소를 연도 텍스트로 교체합니다. 결과적으로 문서에는 The year is 2026과 같은 내용이 남습니다. 웹 API 인자 형식에 맞춘 값 변환의 일반 규칙은 Web IDL 표준에서 정의합니다.

실행 조건과 주의할 점

선언과 실행 모드를 구분해야 합니다

링크된 Lean Rada의 상세 글은 이 별칭을 “constant like $”라고 표현하지만, 제시된 코드에는 const, let, var 중 어느 선언 키워드도 없습니다. 따라서 해당 코드는 상수 선언이 아닙니다.

고전적인 비엄격 모드 스크립트에서 기존 $ 바인딩을 찾을 수 없다면, 한정되지 않은 식별자에 대한 이 할당은 전역 객체에 $라는 속성을 만듭니다. 엄격 모드에서 선언되지 않은 식별자에 값을 할당하면 ReferenceError가 발생합니다. 자바스크립트 모듈은 기본적으로 엄격 모드입니다. 관련 차이는 MDN의 할당 연산자 설명, MDN의 엄격 모드 설명, 선언되지 않은 변수 할당 오류 설명에서 확인할 수 있습니다.

상수 바인딩과 목적이 드러나는 이름을 사용하려면 다음처럼 쓸 수 있습니다. 이 코드는 원문이 아니라 설명을 위한 대안입니다.

const renderHere = (...nodesOrText) =>
  document.currentScript.replaceWith(...nodesOrText);

라이브러리나 다른 페이지 코드가 이미 $를 사용한다면 원문의 할당이 기존 값을 바꿀 수도 있습니다. 공유 페이지에서는 renderHere처럼 충돌 가능성이 낮고 목적이 드러나는 이름이 더 안전합니다.

실행 시점과 보안 정책의 제약이 있습니다

document.currentScript는 나중에도 유지되는 고정 참조가 아닙니다. 이벤트 처리기나 비동기 콜백처럼 초기 스크립트 처리 이후에 접근하면 현재 스크립트 요소를 가리키지 않습니다. 모듈 스크립트에서도 이 속성은 현재 모듈의 <script> 요소를 제공하지 않습니다. 따라서 이 기법은 페이지를 읽는 동안 즉시 실행되는 고전적인 인라인 스크립트를 전제로 합니다. 이 범위는 MDN의 Document.currentScript 설명에 명시되어 있습니다.

사이트의 콘텐츠 보안 정책(Content Security Policy)이 인라인 스크립트를 허용하지 않는 경우에는 적절한 nonce나 해시 같은 허용 근거 없이 이 패턴을 사용할 수 없습니다. 인라인 스크립트의 허용 조건은 MDN의 CSP script-src 설명에서 확인할 수 있습니다.

원문의 “작은 템플릿 언어”라는 표현

Simon Willison의 원문은 이 축약 함수를 사용하면 “작은 템플릿 언어”를 얻는다고 설명합니다. 이는 표준이 정의한 별도 언어가 생긴다는 뜻이라기보다, HTML 안에서 계산 결과를 표시할 자리에 짧은 호출을 놓을 수 있다는 비유로 이해하는 것이 정확합니다.

이 기법은 현재 스크립트 요소를 찾아 교체하는 DOM 조작을 짧게 숨깁니다. 변수 치환, 조건문, 반복, 이스케이프 정책을 갖춘 일반적인 템플릿 시스템 전체를 제공하지는 않습니다.

정리

하이라이트는 $라는 유효한 식별자에, 모든 호출 인자를 배열로 모으는 화살표 함수를 할당하는 부분입니다. 전체 함수에서는 다시 그 배열을 여러 인자로 펼쳐 현재 실행 중인 인라인 스크립트 요소를 교체합니다. 같은 ...가 매개변수 위치에서는 “모으기”, 호출 위치에서는 “펼치기” 역할을 한다는 점이 핵심입니다.

이 축약형은 상수 선언이 아니며, 고전적인 비엄격 모드의 동기 인라인 스크립트라는 실행 조건이 있습니다. 전역 이름 충돌, 모듈 및 비동기 실행의 제한, 사이트의 콘텐츠 보안 정책도 함께 고려해야 합니다.
