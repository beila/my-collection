먼저 알아야 할 공통 개념

값, 타입, 종류

Haskell에서 값(value)의 타입(type)은 그 값이 어떤 종류의 값인지 나타냅니다. 예를 들어 실행 시 사용할 수 있는 True는 타입 Bool의 값입니다. 종류(kind)는 타입이나 타입 수준 표현을 분류합니다. GHC의 데이터 타입 승격 설명에 따르면 DataKinds 확장은 데이터 생성자를 타입 수준으로 승격해 이런 표현을 가능하게 합니다.

표현 수준과 의미
True :: Bool True는 값이고 Bool은 그 값의 타입입니다.
'True :: Bool 'True는 승격된 생성자이고 Bool은 그 타입 수준 표현의 종류입니다.
ver :: PeanoNat ver는 타입 수준 버전 변수이고 PeanoNat은 그 종류입니다.
event :: Symbol event는 타입 수준 이벤트 이름 변수이고 Symbol은 그 종류입니다.

여기서 ::의 오른쪽은 첫 행에서는 값의 타입이고 나머지 행에서는 타입 수준 표현의 종류입니다. 작은따옴표는 승격된 생성자를 가리키거나 다른 이름과 구별하는 표기이며 문자열을 감싸는 기호가 아닙니다.

원문에서 보조 클래스 ConsecutiveUpcast의 매개변수는 순서대로 최신 버전 여부인 isLatest, 버전인 ver, 이벤트 이름인 event입니다. 타입 패밀리(type family) IsLatest는 버전과 최대 버전을 비교해 타입 수준의 'True 또는 'False를 계산합니다. GHC는 이 결과에 맞는 인스턴스를 선택합니다. 런타임 불리언 값을 받아 case로 분기한다는 뜻은 아닙니다. 선택된 메서드는 실제 페이로드를 전달받았을 때 값을 변환합니다. Hindsight의 고정된 구현

버전에는 0과 후속자(successor)로 수를 표현하는 페아노 수(Peano number)를 사용합니다. 예를 들어 타입 수준의 'PeanoSucc ver는 ver의 다음 버전을 나타냅니다. 이 구현은 Nat과 PeanoNat을 별도 표현으로 다루며 타입 패밀리로 명시적으로 변환합니다. 이는 내장 Nat에서 타입 수준 연산이나 재귀가 불가능하다는 뜻은 아닙니다. 페아노 수와 변환의 구현

하이라이트별 해설

타입 수준의 'True는 무엇을 뜻하나요?

하이라이트: 'True

원문 문맥:

When the Bool is 'True (at latest): one instance provides identity

이 문장은 원문의 “How It Works: Default Implementations and Dispatch” 절에서 보조 클래스의 두 경우를 소개합니다. 여기의 'True는 “현재 버전이 최신이다”라는 타입 수준 계산 결과입니다. 이 결과를 첫 번째 매개변수로 받는 인스턴스는 viaConsecutive = id를 정의하므로, 최신 버전의 페이로드는 추가 변환 없이 반환됩니다. 값 True를 메서드의 일반 인자로 넘기는 것은 아닙니다.

~는 어떤 같음을 요구하나요?

하이라이트: ~

원문 문맥:

instance
    ( ver ~ MaxVersionPeano event
    , PayloadAtVersion ver (EventVersionVector event) ~ CurrentPayloadType event
    ) => ConsecutiveUpcast 'True ver event where
    viaConsecutive = id

첫 번째 ~는 ver와 해당 이벤트의 최대 버전 표현 MaxVersionPeano event가 같은 타입 수준 표현이어야 한다는 동등성 제약(equality constraint)입니다. 실행 중 두 값을 비교해 Bool을 반환하는 (==)가 아닙니다. 이 제약 아래에서 타입 검사기는 양쪽을 같은 것으로 사용할 수 있습니다. GHC의 동등성 제약 설명

바로 아래 두 번째 제약은 다른 같음을 요구합니다. 현재 버전에서 꺼낸 페이로드의 타입이 최신 페이로드의 타입과 같아야 합니다. id는 받은 값을 같은 타입으로 돌려주므로, 이 두 번째 제약이 있어야 여기서 요구하는 입력과 출력 타입에 id를 사용할 수 있습니다. 첫 번째는 버전 인덱스의 같음이고, 두 번째는 페이로드 타입의 같음입니다.

instance 다음의 괄호는 무엇을 묶나요?

하이라이트:

instance
    (

원문 문맥:

instance
    ( ver ~ MaxVersionPeano event
    , PayloadAtVersion ver (EventVersionVector event) ~ CurrentPayloadType event
    ) => ConsecutiveUpcast 'True ver event where
    viaConsecutive = id

줄바꿈 뒤의 괄호는 일반 값으로 전달되는 튜플이 아니라 인스턴스 문맥(instance context)입니다. 쉼표로 구분된 두 제약을 묶고, => 뒤에서 어떤 인스턴스를 정의하는지 밝힙니다. 이 예에서는 ConsecutiveUpcast 'True ver event가 인스턴스 헤드(instance head)이며, where 뒤는 그 인스턴스의 메서드 구현입니다. 즉 이 헤드에 해당하는 인스턴스를 사용할 때 문맥의 제약도 충족해야 합니다. 인스턴스 선택은 헤드에 따라 이루어지며, 괄호 안의 제약을 런타임 분기 조건으로 검사하는 것은 아닙니다. GHC의 인스턴스 선언과 해석

원문의 사용자 측 MigrateVersion 선언처럼 메서드를 직접 쓰지 않은 인스턴스는 클래스가 제공한 기본 구현을 사용할 수 있습니다. 이때 해당 기본 구현이 요구하는 제약도 충족되어야 합니다. 따라서 빈 선언과 수동 구현은 서로 다른 선택지입니다. GHC의 기본 메서드 시그니처

viaConsecutive는 @ 뒤의 타입을 어떻게 받나요?

하이라이트: @

원문 문맥:

    viaConsecutive =
        viaConsecutive @(IsLatest ('PeanoSucc ver) event) @('PeanoSucc ver)
            . upcast @(FromPeanoNat ver)

사용자 메모: Is this referring to the type? But does viaConsecutive accept a type?

네. 이 @는 가시적 타입 적용(visible type application)으로, 바로 뒤의 타입 수준 표현을 viaConsecutive의 타입 매개변수에 명시적으로 지정합니다. TypeApplications 확장에서 다형 함수나 메서드의 지정 가능한 타입 변수를 이런 식으로 구체화할 수 있습니다. 이것은 런타임에 타입 객체를 값 인자로 전달하는 호출이 아닙니다. GHC의 가시적 타입 적용 설명

원문에 보이는 PayloadAtVersion ... -> CurrentPayloadType ...는 값 인자와 반환값의 관계를 나타냅니다. 여기에 클래스의 타입 매개변수와 ConsecutiveUpcast 제약까지 포함해야 메서드의 전체 다형 타입을 이해할 수 있습니다. 클래스 메서드의 가시적 타입 인자는 클래스 선언의 매개변수부터 순서대로 지정합니다. 따라서 이 메서드에서는 isLatest, ver, event 순서입니다.

첫 번째 @(IsLatest ('PeanoSucc ver) event)는 다음 버전이 최신인지에 관한 타입 수준 결과를 isLatest에 지정합니다. 바로 뒤의 @('PeanoSucc ver)는 다음 버전 자체를 ver에 지정합니다. 원문에 고정된 실제 구현은 이어서 세 번째 매개변수도 @event로 명시합니다. 원문에 실린 발췌는 이 부분을 생략합니다. 실제 재귀 인스턴스

인용한 식의 .은 함수 합성입니다. 페이로드가 주어지면 오른쪽의 upcast가 먼저 현재 버전을 다음 버전으로 바꾸고, 왼쪽의 viaConsecutive가 그 다음 버전부터 최신 버전까지 이어서 변환합니다. 다음 버전이 이미 최신이면 선택된 'True 인스턴스의 id가 결과를 그대로 돌려줍니다.

정리

기본 구현은 인접 변환을 연결하고, 타입 수준의 최신 버전 여부는 계속할지 멈출지에 맞는 인스턴스를 고릅니다. 동등성 제약은 각 타입 관계를 검사하고, @는 그 선택에 필요한 타입 매개변수를 명시합니다. 타입 검사는 연결되는 입력과 출력의 호환성을 보장하지만, 사용자가 작성한 변환의 업무상 의미나 누락된 과거 데이터의 복구까지 증명하지는 않습니다.

원문의 일부 코드는 설명을 위해 생략되어 있으므로 독립적으로 컴파일되는 전체 프로그램으로 취급하지 않는 것이 좋습니다. 실제 구현에는 추가 동등성 제약과 명시적인 타입 인자가 있습니다.
