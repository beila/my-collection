한 층의 구조에서 재귀 전체로: F-대수와 펼치기 이해하기

해설 대상 원문: Bartosz Milewski, “F-Algebras”

검토일: 2026-11-03

EPUB으로 읽기

Bartosz Milewski의 「F-Algebras」(2017-02-28)는 재귀 자료를 처리하는 프로그램을 두 부분으로 나눕니다. 하나는 한 층을 어떻게 처리할지이고, 다른 하나는 그 처리를 재귀 구조 전체에 어떻게 반복할지입니다. 이 구분을 알면 Fix, unFix, catamorphism, anamorphism이 서로 어떤 일을 맡는지 읽을 수 있습니다.

먼저 한 층과 전체 구조의 관계를 설명하고, 초기 대수에 관한 증명과 주석의 질문을 풀어 봅니다. 이어서 스트림, 소수 생성, 리스트 변환, 렌즈를 타입이 표시된 도식으로 연결합니다. 도식은 이 해설에서 새로 작성했으며, 화살표는 함수나 사상이고 화살표 양 끝은 타입이나 대상입니다.

먼저 구분할 것: 모양, 한 층의 처리, 전체의 처리

자기함자(endofunctor) F는 한 범주 안에서 대상과 사상을 같은 범주의 대상과 사상으로 보냅니다. 프로그래밍 예제에서는 F a를 “다음 단계가 들어갈 자리에 a를 둔 한 층의 모양”으로 읽으면 유용합니다. 이 비유는 원문의 다항식 자료형에 잘 맞습니다. 모든 자기함자가 반드시 나무 모양이라는 뜻은 아닙니다. Ahrens와 Wullaert의 교재는 일반적인 정의와 대수·쌍대대수의 보편 성질을 구분합니다.

원문의 자연수 모양은 다음과 같습니다.

data NatF a = ZeroF | SuccF a

아래는 뒤의 계산 예제를 위해 이 해설에서 추가한 Functor NatF 인스턴스입니다. 원문 선언의 일부는 아닙니다. ZeroF는 그대로 두고 SuccF의 매개변수 자리에만 함수를 적용합니다. Functor의 연산 정의에 맞춰 직접 정의하므로 별도의 자동 유도 확장은 필요하지 않습니다.

instance Functor NatF where
  fmap _ ZeroF = ZeroF
  fmap h (SuccF x) = SuccF (h x)

ZeroF에는 다음 단계가 없고, SuccF a에는 a 자리 하나가 있습니다. a에 전체 자연수 구조를 넣으면 재귀가 되고, a에 이미 계산된 정수를 넣으면 “이전 답을 받아 다음 답을 계산하는 한 단계”가 됩니다.

구분 타입 맡은 일
대수(algebra)의 구조 사상 alg :: F a -> a 한 층에 들어 있는 결과를 모아 결과 하나를 만듭니다.
쌍대대수(coalgebra)의 구조 사상 coalg :: a -> F a 상태 하나에서 한 층의 관찰값과 다음 상태를 만듭니다.
접기(catamorphism) cata alg :: μF -> a 재귀 구조 전체에 한 층의 계산을 반복합니다.
펼치기(anamorphism) ana coalg :: a -> νF 시작 상태에서 한 층의 생성을 반복합니다.

μF는 초기 대수의 운반 대상(carrier), νF는 최종 쌍대대수의 운반 대상을 나타내는 수학적 표기입니다. 두 대상은 존재하지 않을 수도 있고, 존재해도 서로 다를 수 있습니다. 원문처럼 둘 다 Haskell의 Fix f로 표시하는 것은 추가적인 의미론적 가정을 담은 표현입니다. 유한하고 잘 기초화된 나무에 관한 증명과 지연 평가의 무한 자료에 관한 설명을 구분해야 합니다. 초기·최종 대상의 정의, 지연 평가와 재귀 자료의 의미론이 이 차이를 설명합니다.

“초기”는 다른 모든 F-대수로 가는 구조 보존 사상이 정확히 하나 있다는 뜻입니다. “최종”은 반대로 다른 모든 F-쌍대대수에서 들어오는 구조 보존 사상이 정확히 하나 있다는 뜻입니다. 단순히 함수의 입력과 출력을 뒤집어 얻는 성질이 아닙니다.

합타입은 왜 필요한가요?

하이라이트: we need coproducts to complete our algebraic shenanigans.

원문 문맥:

Finally, we need coproducts to complete our algebraic shenanigans.

사용자 메모: “What’s coproduct and why do we need it?”

쌍대곱(coproduct)은 여기서 여러 종류의 입력 중 어느 종류인지 구별하면서 하나로 묶는 방법입니다. 집합에서는 태그를 붙인 서로소 합집합으로 구현합니다. 보통 합집합처럼 같은 값이 합쳐지는 것이 아니라, 왼쪽에서 온 값과 오른쪽에서 온 값을 구별합니다. Haskell의 Either가 이 형태를 보여 줍니다. 쌍대곱의 보편 성질, Haskell의 Either 정의를 참고할 수 있습니다.

원문의 모노이드 예제에는 입력 없는 단위원 연산 1 -> m과 입력 둘을 받는 연산 m × m -> m이 있습니다. 두 연산을 한 함수에 담으려면 입력이 “단위원을 요청하는 경우”인지 “두 값을 결합하는 경우”인지 표시해야 합니다. 원문의 선언은 그 선택지를 표현합니다.

data MonF a = MEmpty | MAppend a a

|는 두 생성자 중 하나를 고르는 합을 나타냅니다. MAppend 뒤의 두 필드는 값 둘이 함께 필요하다는 곱을 나타냅니다. 따라서 모양은 1 + a × a입니다. 대수 MonF m -> m은 MEmpty일 때 단위원을 반환하고, MAppend x y일 때 두 값을 결합합니다.

쌍대곱에는 각 입력을 넣는 사상 A -> A+B, B -> A+B가 있습니다. A -> C와 B -> C가 주어지면 각 경우를 해당 함수로 처리하는 A+B -> C가 유일하게 정해집니다. 원문은 함수 공간의 지수법칙으로 이 결과를 유도하지만, 이미 주어진 두 사상을 합치는 단계 자체에는 쌍대곱의 보편 성질만 있으면 됩니다. 지수 대상은 그 유도 방식에 쓰이는 추가 구조입니다. 또한 MonF m -> m이라는 타입만으로 결합법칙과 단위원 법칙이 보장되지는 않습니다. 이 법칙은 별도로 요구해야 합니다.

초기성이 왜 동형을 보장하나요?

하이라이트:

j is an isomorphism between F i and i:

F i ≅ i

원문 문맥:

This shows that m is the inverse of j and therefore j is an isomorphism between F i and i:

F i ≅ i

사용자 메모: “Why?”

출발점은 (i, j)가 초기 대수라는 가정이며, j : F i -> i입니다. 동형임을 보이려면 반대 방향 m : i -> F i를 만들고 두 합성이 모두 항등임을 보여야 합니다. 이것이 람베크 정리(Lambek’s theorem)의 증명입니다. 교재의 초기 대수 정의와 연습문제 185에 같은 정리가 나옵니다.

먼저 j에 함자 F를 적용하면 F j : F(F i) -> F i를 얻습니다. 따라서 (F i, F j)도 대수입니다. 초기성 때문에 이 대수로 가는 유일한 대수 준동형 m이 존재합니다. 아래는 그 조건을 표시한 새 도식입니다.

F i  -------- F m --------> F(F i)
 |                            |
 j                            F j
 |                            |
 v                            v
 i   --------- m --------->   F i

m ∘ j = F j ∘ F m

반대 방향인 j 자체도 (F i, F j)에서 (i, j)로 가는 대수 준동형입니다. 그 준동형 조건의 양쪽은 모두 j ∘ F j이므로 같습니다. 따라서 합성 j ∘ m은 초기 대수에서 자기 자신으로 가는 대수 준동형입니다. 초기성에 의해 그런 사상은 정확히 하나이고, 항등 사상도 그 조건을 만족하므로 다음을 얻습니다.

j ∘ m = id_i

아직 역함수 조건 하나가 남습니다. 위 도식의 교환 조건과 함자의 합성 보존을 쓰면 직접 계산할 수 있습니다.

m ∘ j = F j ∘ F m
      = F(j ∘ m)
      = F(id_i)
      = id_(F i)

이제 양방향 합성이 모두 항등이므로 m은 j의 역이고 F i ≅ i입니다. 논리 방향은 초기 대수이면 고정점이라는 것입니다. 고정점이면 언제나 초기 대수라는 역명제는 나오지 않습니다.

Fix f가 초기 대수라는 말에는 무엇이 더 필요한가요?

하이라이트: We call the initial algebra Fix f.

원문 문맥:

Let’s rewrite the initiality condition using Haskell notation. We call the initial algebra Fix f. Its evaluator is the contructor Fix.

사용자 메모: “Why is Fix the initial algebra?”

엄밀히는 초기 대수는 운반 타입만이 아니라 구조 사상까지 포함한 쌍입니다. 원문은 (Fix f, Fix)를 운반 타입의 이름으로 줄여 부릅니다. 다음 선언은 한 층을 감싸거나 벗기는 표현을 제공하지만, 선언만으로 임의의 범주에서 초기성이 증명되지는 않습니다.

newtype Fix f = Fix (f (Fix f))

유한하고 잘 기초화된 다항식 나무에서는 초기성을 별도로 보일 수 있습니다. 임의의 alg :: f a -> a를 정하면, 잎부터 alg를 적용하는 구조적 재귀로 Fix f -> a를 만들 수 있습니다. 이것이 존재성입니다. 유일성은 나무에 대한 귀납법으로 보입니다. 잎에서는 구조 보존 조건이 결과를 결정하고, 자식들의 결과가 이미 결정되어 있으면 부모의 결과도 alg가 결정합니다. 따라서 다른 구조 보존 함수가 같은 나무에서 다른 결과를 낼 수 없습니다. 초기 대수와 catamorphism의 정의가 요구하는 두 조건을 이렇게 충족합니다.

NatF로 쓰면 더 구체적입니다. 아래는 이 해설에서 만든 계산 예제입니다.

count :: NatF Integer -> Integer
count ZeroF = 0
count (SuccF n) = n + 1

초기 대수에서 이 대수로 가는 사상 h는 구조 보존 때문에 다음 식을 만족해야 합니다.

h (Fix ZeroF)     = count ZeroF = 0
h (Fix (SuccF t)) = count (SuccF (h t)) = h t + 1

유한한 자연수 나무에 대해서는 이 두 식이 모든 결과를 결정합니다. 반면 Haskell의 지연 평가에는 무한한 값과 정의되지 않은 값도 있으므로 이 유한 귀납법을 그대로 모든 Haskell 값에 적용할 수는 없습니다. 원문의 표기는 적절한 재귀 자료 의미론을 압축한 설명으로 읽는 편이 정확합니다. newtype의 언어 규칙, 접기와 펼치기의 의미론적 조건이 관련 경계를 설명합니다.

하이라이트: unFix

원문 문맥:

사용자 메모: “What does unFix mean? I can faintly understand what Fix is from the recursive definition. But I can’t infer what unFix means by inverting Fix”

unFix는 Fix가 감싼 값을 패턴 매칭으로 꺼내는 함수입니다. 숫자의 역수를 구하거나 재귀 전체를 역산하지 않습니다. 원문의 정의를 그대로 보면 동작이 드러납니다.

unFix :: Fix f -> f (Fix f)
unFix (Fix x) = x

다음은 새로 만든 예제이며 z와 one은 유한한 자연수 나무입니다.

z = Fix ZeroF
one = Fix (SuccF z)

unFix one의 결과는 SuccF z입니다. 바깥 Fix 하나만 없어졌고, 자식 z는 여전히 Fix NatF입니다. 정수 1로 평가되거나 모든 재귀 층이 제거되지 않습니다.

Fix   : f (Fix f) -> Fix f
unFix : Fix f     -> f (Fix f)

unFix (Fix x) = x
Fix (unFix t) = t

“역”은 감싼 뒤 벗기거나 벗긴 뒤 감싸면 원래 표현을 얻는다는 뜻입니다. 이름을 unFix라고 붙이면 컴파일러가 역함수를 자동으로 만들어 주는 것도 아닙니다. 원문은 그 함수를 직접 정의했습니다. 또한 newtype의 감싸기와 벗기기는 표현 변환이며 나무 전체를 순회하는 작업이 아닙니다. Haskell 2010의 데이터형 이름 바꾸기 규칙이 이 점을 명시합니다.

Catamorphism은 한 층 계산으로 전체를 접습니다

하이라이트: catamorphism

원문 문맥:

This higher order function is called a catamorphism:

You can easily convince yourself that the catamorphism for this algebra, cata fib, calculates Fibonacci numbers.

사용자 메모: “What is this?”

카타모피즘(catamorphism)은 한 층의 대수 alg를 받아 재귀 구조 전체를 계산하는 접기입니다. 원문의 코드는 다음과 같습니다.

cata :: Functor f => (f a -> a) -> Fix f -> a
cata alg = alg . fmap (cata alg) . unFix

오른쪽부터 읽으면 unFix로 한 층을 드러내고, fmap (cata alg)로 재귀 자리의 자식들을 계산한 뒤, alg로 그 결과들을 합칩니다. fmap이 바꾸는 것은 함자의 매개변수 자리입니다. 예를 들어 NatF에서는 SuccF 안의 자식을 바꾸고 ZeroF에는 적용할 자식이 없습니다. 함자 연산의 정의와 초기 대수의 보편 성질이 이 계산을 연결합니다.

f (Fix f) ------- Fix -------> Fix f
    |                            |
    | fmap (cata alg)            | cata alg
    v                            v
   f a --------- alg ----------> a

(cata alg) ∘ Fix = alg ∘ fmap (cata alg)

앞에서 추가한 Functor NatF 인스턴스와 count를 사용하면 cata count one은 자식 z를 0으로 계산한 다음 count (SuccF 0)을 계산하여 1을 얻습니다. 재귀는 cata가 맡고, count는 이미 계산된 자식의 답만 받습니다. 유한한 나무이고 각 한 층 계산도 종료한다면 전체 계산도 종료합니다.

cata는 대수를 받는 고차 함수이고, cata alg가 도식의 유일한 사상 m입니다. 리스트의 foldr는 이 패턴의 익숙한 특수형입니다. 빈 리스트의 결과와 머리·꼬리의 결과를 결합하는 함수가 리스트 대수의 두 경우를 정합니다. Haskell의 foldr 정의에서도 이 두 입력을 확인할 수 있습니다.

Anamorphism도 그 도식의 m인가요?

하이라이트: anamorphism

원문 문맥:

Just like a catamorphism can be used to evaluate an initial algebra, an anamorphism can be used to coevaluate a terminal coalgebra:

사용자 메모: “Is this m in the previous diagram? Catamorphism was easy to understand because it had the diagram exactly depicting it. Show me similar diagram for anamorphism”

네, 쌍대대수 coalg를 고정하면 ana coalg가 최종 쌍대대수로 가는 유일한 사상 m입니다. ana 자체는 coalg를 인자로 받으므로 아직 그 사상이 아닙니다. 일반적인 도식은 다음과 같습니다. out은 최종 쌍대대수의 구조 사상입니다. 최종 쌍대대수와 anamorphism의 정의가 바로 이 교환 조건을 사용합니다.

a  ----------- coalg ----------> F a
|                                 |
| m = ana coalg                   | F m
v                                 v
νF ------------ out ----------> F(νF)

out ∘ m = F m ∘ coalg

위쪽을 먼저 가면 시작 상태에서 한 층과 다음 상태들을 얻고, 오른쪽으로 내려오면서 다음 상태들을 재귀 구조로 펼칩니다. 왼쪽을 먼저 가면 전체 재귀 구조를 만든 뒤 out으로 한 층을 관찰합니다. 두 경로가 같아야 같은 생성 규칙을 따르는 결과입니다.

쌍대 람베크 정리에 의해 out의 역 in이 존재하면 이 조건을 m = in ∘ F m ∘ coalg로 바꿀 수 있습니다. 원문의 Haskell 표현에서는 in이 Fix, out이 unFix에 대응합니다.

ana :: Functor f => (a -> f a) -> a -> Fix f
ana coalg = Fix . fmap (ana coalg) . coalg

먼저 coalg로 한 층을 만들고, 다음 상태 자리를 재귀적으로 펼친 뒤, Fix로 한 층을 감쌉니다. 앞서 구분한 것처럼 일반 범주의 νF와 Haskell 표현의 대응에는 의미론적 조건이 필요합니다.

coevaluate는 무엇을 뜻하나요?

하이라이트: coevaluate

원문 문맥:

Just like a catamorphism can be used to evaluate an initial algebra, an anamorphism can be used to coevaluate a terminal coalgebra:

사용자 메모: “?”

이 문맥에서는 시작 상태로부터 구조를 펼쳐 생성한다는 뜻으로 읽으면 됩니다. 이는 저자의 용어 사용에 대한 해석입니다. evaluate가 구조에서 결과로 가는 것을 가리키므로 저자는 반대 방향의 생성에 coevaluate라는 말을 붙였습니다. 정식 동작은 앞 도식의 anamorphism, 즉 unfold로 설명할 수 있습니다. 원문의 해당 문장과 표준 라이브러리의 unfold 설명이 그 읽기를 뒷받침합니다.

임의의 계산 결과로부터 과거 입력을 복원한다는 뜻은 아닙니다. coalg가 상태에서 다음 층을 만드는 규칙을 제공해야 합니다. 다른 범주론 문맥의 “coevaluation 사상”이라는 용어와 동일시할 필요도 없습니다.

스트림부터 렌즈까지, 각각의 화살표를 연결하기

하이라이트: StreamF

원문 문맥:

A canonical example of a coalgebra is based on a functor whose fixed point is an infinite stream of elements of type e. This is the functor:

data StreamF e a = StreamF e a
  deriving Functor

사용자 메모: “Draw anamorphism diagrams that each shows StreamF, Stream, era, primes, toListC, unfoldr, Maybe, set, get, Store along with related concepts indicated”

요청된 이름은 모두 아래 도식에 넣었습니다. 다만 모두 anamorphism은 아닙니다. toListC는 catamorphism이고, set과 get은 Store 쌍대대수를 구성합니다. 이 구분을 유지해야 화살표의 타입과 역할이 맞습니다.

StreamF는 한 층이고 Stream은 이어진 전체입니다

StreamF e a에는 지금 내보낼 e 하나와 다음 상태 a 하나가 있습니다. 원문의 직접 재귀형은 다음과 같습니다.

data Stream e = Stream e (Stream e)

Stream e와 Fix (StreamF e)는 같은 구조를 표현할 수 있지만, Haskell에서 정의상 같은 타입은 아닙니다. 두 표현 사이에는 생성자를 대응시키는 변환이 필요합니다. 아래 도식의 아래쪽은 Fix 표현을 사용합니다. 원문의 스트림 예제, 새 자료형과 타입의 구분을 바탕으로 한 도식입니다.

a  ------------ coalg -----------> StreamF e a
|                                      |
| ana coalg                            | fmap (ana coalg)
v                                      v
Fix (StreamF e) ---- unFix -------> StreamF e (Fix (StreamF e))

Stream e  <--- 생성자를 대응시키는 변환 --->  Fix (StreamF e)

e 자리는 관찰값이고 a 자리만 다음 재귀 단계입니다. 따라서 fmap h (StreamF e next)는 StreamF e (h next)가 됩니다. 스트림 모양에는 빈 경우가 없으므로, 계속 관찰 가능한 스트림을 만들려면 매번 다음 층을 제공할 수 있어야 합니다.

era는 한 단계 함수이고 primes는 생성된 값입니다

원문의 코드는 다음과 같습니다.

era :: [Int] -> StreamF Int [Int]
era (p : ns) = StreamF p (filter (notdiv p) ns)
    where notdiv p n = n `mod` p /= 0
primes = ana era [2..]
[Int] ------------ era -----------> StreamF Int [Int]
  |                                      |
  | ana era                              | fmap (ana era)
  v                                      v
Fix (StreamF Int) ---- unFix ------> StreamF Int (Fix (StreamF Int))

입력값 [2..] -- ana era --> 결과값 primes

마지막 줄의 [2..]와 primes는 타입이 아니라 값입니다. 함수 화살표의 이름은 ana era입니다. 첫 단계에서는 후보 2,3,4,5,…에서 2를 내보내고 남은 후보에서 2의 배수를 거릅니다. 다음에는 3을 내보내고 남은 후보에서 3의 배수를 거릅니다.

[2,3,4,5,6,7,8,9,...] -> StreamF 2 [3,5,7,9,...]
[3,5,7,9,11,13,...]   -> StreamF 3 [5,7,11,13,...]

이 전이는 수학적으로 계속되는 후보열을 설명한 것입니다. 원문 코드의 Int는 유한 범위의 정수이며 [2..]도 그 범위에 제한됩니다. 또한 era []의 정의가 없습니다. 따라서 원문 구현을 무조건 끝없이 작동하는 소수 생성기라고 해석하면 안 됩니다. 수학적 무한열을 구현하려는 별도 변형에서는 Integer 같은 타입과 생산성 조건을 검토해야 합니다. Haskell의 정수형과 열거 규칙이 이 제한을 설명합니다.

toListC는 같은 모양을 리스트로 접습니다

다음은 원문의 코드입니다.

toListC :: Fix (StreamF e) -> [e]
toListC = cata al
   where al :: StreamF e [e] -> [e]
         al (StreamF e a) = e : a
StreamF e (Fix (StreamF e)) ---- Fix ----> Fix (StreamF e)
             |                                  |
             | fmap toListC                     | toListC
             v                                  v
       StreamF e [e] -------- al -------------> [e]

 toListC ∘ Fix = al ∘ fmap toListC

al은 머리 e를 이미 변환된 꼬리 리스트 앞에 붙입니다. 여기서는 무한 스트림의 끝까지 갔다가 유한 결과를 반환하는 계산을 하는 것이 아닙니다. Haskell의 지연 평가에서는 e : a의 앞부분을 사용하기 위해 꼬리 a 전체를 먼저 계산할 필요가 없습니다. 생산적인 입력 스트림이라면 필요한 유한 접두부를 차례로 관찰할 수 있습니다. 생산성이란 요청한 유한 부분을 유한한 작업으로 얻을 수 있다는 뜻이며, 무한 자료 전체의 생성이 종료한다는 뜻은 아닙니다. Haskell의 리스트 구성과 foldr, 지연 평가 재귀 구조의 의미론이 이 해석을 뒷받침합니다.

Maybe는 리스트 펼치기에 종료 선택지를 더합니다

원문의 타입은 다음과 같습니다.

unfoldr :: (b -> Maybe (a, b)) -> b -> [a]

혼동을 줄이기 위해 아래 도식에서는 원소 타입을 e, 상태 타입을 b로 씁니다. Nothing은 중단이고 Just (e, b)는 원소 하나와 다음 상태입니다. 다음 outList, mapSecond, step 표기는 도식을 설명하기 위해 새로 도입했습니다.

b  ------------ step ------------> Maybe (e,b)
|                                      |
| unfoldr step                         | fmap (mapSecond (unfoldr step))
v                                      v
[e] ----------- outList ----------> Maybe (e,[e])
outList [] = Nothing
outList (x:xs) = Just (x,xs)

mapSecond h (x,y) = (x,h y)

오른쪽 화살표는 Maybe 안의 쌍에서 두 번째 성분만 펼칩니다. 단순히 fmap (unfoldr step)이라고 쓰면 쌍 전체를 상태로 취급하게 되어 이 타입에 맞지 않습니다. Nothing은 그대로 남고, Just (x,next)는 Just (x,unfoldr step next)가 됩니다. 이 도식은 출력 리스트를 한 층 관찰하는 일과 시작 상태에서 한 층 생성하는 일이 일치함을 보여 줍니다. 실제로 유한 리스트가 되는지는 step이 결국 Nothing을 반환하는지에 달려 있습니다. Haskell 2010의 unfoldr 명세가 이 종료 규칙을 제공합니다.

set, get, Store는 렌즈의 한 층을 구성합니다

원문의 타입과 선언은 다음과 같습니다. 여기서 a는 전체 구조 타입이고 s는 그 안에서 초점을 맞춘 값의 타입입니다.

set :: a -> s -> a
get :: a -> s
data Store s a = Store (s -> a) s

전체 값 x :: a를 고정하면 set x :: s -> a는 새 초점 값을 받아 전체를 다시 만드는 함수이고, get x :: s는 현재 초점 값입니다. 이 둘을 묶는 다음 lens는 해설에서 만든 이름과 코드입니다.

lens x = Store (set x) (get x)
                    x : a
                   /     \
             set x         get x
            s -> a           s
                   \       /
             Store (set x) (get x)
                      |
                      v
                  Store s a

          a -------- lens --------> Store s a

원문의 a -> (s, s -> a)는 값이 먼저 오는 쌍이고, Store 생성자는 함수가 먼저 옵니다. 포장할 때 순서가 바뀝니다. Store s의 함자 작용도 새로 풀어 쓰면 다음과 같습니다.

fmap h (Store k s0) = Store (h . k) s0

이 식은 일반적인 Functor 인스턴스 선언 전체가 아니라 해당 모양의 함자 작용을 설명한 것입니다. s0는 그대로 두고, 전체 구조를 만드는 함수의 결과에 h를 합성합니다.

따라서 lens :: a -> Store s a는 쌍대대수입니다. 하지만 이 사실만으로 a가 최종 쌍대대수이거나 lens가 anamorphism이라는 결론은 나오지 않습니다. 올바른 렌즈에는 읽은 값을 다시 쓰면 원래 구조가 유지되는 등의 법칙이 더 필요합니다. O’Connor의 「Functor is to Lens as Applicative is to Biplate」는 렌즈 법칙과 Store 코모나드 쌍대대수 법칙의 대응을 설명합니다.

모든 자기함자에 초기 대수와 최종 쌍대대수가 있나요?

하이라이트: The initial algebra is the so called least fixed point, and the terminal coalgebra is the greatest fixed point.

원문 문맥:

In general, an endofunctor may have many (or no) fixed points. The initial algebra is the so called least fixed point, and the terminal coalgebra is the greatest fixed point.

사용자 메모: “Does this imply endodunctors have both algebra and coalgebra? Always both?”

항상 그렇지는 않습니다. 먼저 개별 대수·쌍대대수가 있다는 것과 초기 대수·최종 쌍대대수가 있다는 것을 나누어야 합니다. F a -> a가 하나 있다고 해서 다른 모든 대수로 가는 유일한 사상이 생기지는 않습니다. a -> F a도 마찬가지입니다. 대수와 보편 대상의 정의가 이 둘을 구분합니다.

임의의 범주에서는 개별 대수와 쌍대대수조차 없을 수 있습니다. 다음은 정의에서 직접 구성한 반례입니다. 대상 A, B와 각각의 항등 사상만 있는 범주에서 F가 두 대상을 바꾸게 합니다. 그러면 대수를 위해 필요한 B -> A나 A -> B가 없고, 쌍대대수를 위한 반대 방향 사상도 없습니다.

집합의 범주에서는 상황이 조금 좋습니다. 종 대상인 한 원소 집합 1로 가는 함수 F 1 -> 1은 항상 있고, 빈집합 0에서 나가는 함수 0 -> F 0도 항상 있습니다. 따라서 모든 집합 자기함자에는 적어도 개별 대수 하나와 개별 쌍대대수 하나가 있습니다. 그러나 이들이 초기·최종이라는 뜻은 아닙니다.

초기·최종 대상이 모두 없을 수 있다는 반례는 전체 멱집합 함자 P입니다. 칸토어 정리에 의해 어떤 집합 X도 P X와 동형일 수 없습니다. 초기 대수나 최종 쌍대대수가 있었다면 람베크 정리에 의해 그런 동형이 생겨야 하므로 둘 다 존재하지 않습니다. Hofmann과 Nora의 「Hausdorff coalgebras」 서론이 이 반례를 설명합니다.

둘 다 존재해도 같을 필요는 없습니다. 다음은 초기·최종 대수 교재의 정의와 예제를 집합의 범주에서 읽은 비교입니다.

자기함자 초기 대수의 운반 집합 최종 쌍대대수의 운반 집합
F X = 1 + X 자연수 집합이며 유한하게 후속자를 적용한 값입니다. 자연수에 끝없이 후속되는 행동 ∞를 더한 집합입니다.
F X = E × X, E가 비어 있지 않은 경우 빈집합입니다. E의 무한 스트림 집합입니다.

두 번째 행의 초기 대수가 빈집합인 이유는 E × 0 = 0이고, 빈집합에서 어떤 대수로든 가는 함수가 유일하기 때문입니다. 반면 최종 쌍대대수는 상태를 관찰하면서 얻는 무한열을 모두 담습니다. 따라서 집합의 범주에서 생산적인 무한 스트림을 초기 대수라고 부를 수는 없습니다.

“최소·최대 고정점”은 단순히 원소 수가 가장 작거나 크다는 뜻으로 이해하면 안 됩니다. 초기·최종의 보편 성질이나, 지정된 순서를 갖춘 의미론에서의 최소·최대라는 뜻을 확인해야 합니다. 원문에서 Haskell의 두 표현이 일치한다고 하는 부분은 지연 평가와 부분 값을 다루는 적절한 도메인 의미론을 배경으로 합니다. 모든 자기함자나 모든 Haskell 함수에 조건 없이 성립하는 명제는 아닙니다. Meijer·Fokkinga·Paterson의 재귀 자료 연구는 집합에서의 유한·무한 자료 구분과 지연 언어의 접근을 대비합니다.

연결해서 읽기

F는 한 층의 모양을 정하고, alg와 coalg는 각각 한 층을 계산하거나 생성합니다. Fix와 unFix는 재귀 표현에서 한 층을 감싸고 벗깁니다. 전체 구조를 반복해서 다루는 일은 cata alg와 ana coalg가 맡습니다. 초기성과 최종성은 이 전체 처리 함수의 존재성과 유일성을 말하는 별도의 성질입니다.

원문의 도식을 볼 때는 먼저 양 끝의 타입을 적고, m이 한 층의 함수인지 전체의 함수인지 확인하면 됩니다. 스트림의 era는 한 층을 만들고, ana era는 그 층들을 이어 붙입니다. toListC는 같은 스트림 모양을 리스트로 접고, 렌즈는 Store라는 다른 모양의 쌍대대수를 구성합니다. 이 구분을 유지하면 서로 비슷한 재귀 식이 왜 다른 역할을 하는지 설명할 수 있습니다.
