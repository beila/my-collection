2026-11-07 · comment — One example that comes to my mind is libopus: github.com/xiph/opus

If you have structs that might need to be extended, you can use "versioned structs". One popular technique is to include the struct size as the first field. The struct size is set to `offsetof(mystruct, lastmember) + sizeof(lastmember)` and the receiver of the struct can use this to check if a member exists. The ARA API is a good example: github.com/Celemony/ARA_API/blob/65ec5c43b943a48cb54...

2026-11-07 · comment — If you do version and size as the first two fields, you're basically there to backwards and forwards compatibility. Callers can request the size of the struct, allocate a buffer, and read out the parts they need. They can also check specific versions for what they support and ignore newer versions.

It also helps if you only append to the end of the struct for newer fields.

2026-11-07 · comment — since you are using kitty, make sure you know these:

- kitten, a lot, they are useful. I will name a few. kitten ssh, keep a long lived connection so that you need to authenticated once for the whole kitty window. kitten tranfer, transfer files between remote and local when you are inside the remote host. kitten clipboard, take data on the remote host to the local clipboard.

- customize your keyboard shortcuts to be more efficient on creating new tab, moving between tab, keep the current working directory when creating new tab, split panel (even you are on the remot host).

- tune the performance configuration.

- on macOS, you can hide the title bar of the window, give more minimal look.

- take time to learn from their documentation, a lot of useful things to be known.

- the author is uncompromised on the performance, e.g. github.com/kovidgoyal/kitty/issues/884

- don't ask the author to change kitty icon (but you can change it yourself, I did): sw.kovidgoyal.net/kitty/faq/#i-do-not-like-the-kitty...
