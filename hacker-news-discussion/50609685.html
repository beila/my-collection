I love the transparency, or at least given technical details, that Zhipu provide - a refreshing change from the locked-down approach of the western companies, and an interesting glimpse into the direction of SOTA LLMs.

Looped Transformers are an obvious direction even if there are still problems to be worked out. The original Transformer is a bit like an unrolled for loop, and rather unnaturally pairs different sets of weights, both for attention and feed forward (knowledge) with different "layers" (aka loop iterations). Far more natural is to strive for something more like our brain's thalamo-cortical loop and association cortex, where "thought" is iterative and there are no restrictions as to what patterns/knowledge get applied when.

A similar idea has been explored before ("Universal Transformer", 2019), seemingly going nowhere, but perhaps "necessity is the mother of invention" and compute-starved Chinese companies are finding a way to make it work.

For those wondering what loop transformers are:

LLMs have layers of data, called weights. During inference, each layer gets computed once. Moving weights from HBM memory to the chip is a major bottleneck because to generate a token, you need to move an entire layer into the chip, compute once, move it out, move the next layer in. Hence, memory bandwidth has been the #1 bottleneck for inference.

A loop transformer optimizes this bottleneck. Instead of one layer being computed once, it will compute the same layer multiple times, increasing the model intelligence without relying memory bandwidth as much. Bandwidth is still important, but not as much anymore.

More intelligence is squeezed by using the GPU compute that is typically sitting idle during inference.

2026-11-23 · comment
If I understand you correctly, I think you are incorrect.

Looped transformers allow models to do more compute in the forward pass for the same total parameter budget (e.g., required VRAM to store the model). This doesn't inherently optimize the memory bandwidth bottleneck. A simple way to see this is that if we reuse a layer during the forward pass, we still need to fetch its weights from HBM again, which incurs additional memory bandwidth usage.

The main advantage is more computation for a fixed parameter count and model-weight VRAM footprint, not more computation for a fixed HBM bandwidth budget.
