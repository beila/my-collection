If these builds are running in a WASM environment, it means we can enforce stricter control over them than was available when they were originally authored. Rather than having it be a convention that using a source of randomness in your builds is a bad idea, we can just take the random number generator away from the build. Rather than suggesting that network connections in builds are likely problematic, we can deny the build access to the network and ensure it still runs. The nix sandbox can only go so far to encourage determinism, but I think wasm can take it even further.

2026-11-24 · comment
While it's neat that we have tools to port stuff from one Turing complete runtime to another, the whole "JavaScript" element of the linked page is tenuous. WASM is a virtual machine made to run in web browsers. We had an asm.js that was the precursor to more easily transpile other languages -- transpiling between Turing complete languages has been a thing forever -- but extrapolating that to mean anything running in WASM is "written in JavaScript" is silliness.

It's a legitimately funny basis for a piece, but it's intellectually misleading.

And of course none of this is remotely new. We've had emscripten to compile LLVM intermediate code to WASM, or JavaScript for that matter, for about a decade and half.
