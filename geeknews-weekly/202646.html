[GN#384] 클라우드 없이 어디까지 테스트할 수 있을까?

AWS는 우리가 많이 쓰는 클라우드지만, 그동안 여러 서비스를 한꺼번에 테스트할 수 있는 공식 에뮬레이터가 없었습니다. S3에 파일을 올리고 SQS로 작업을 넘기는 기본적인 흐름도 노트북에서 처음부터 끝까지 돌려보려면 별도의 도구가 필요했는데요. 그 빈자리를 LocalStack 같은 외부 프로젝트가 채워왔습니다.

긱뉴스 초기에 소개해 드렸던 LocalStack도 7년 동안 많이 달라졌습니다. 지금은 무료 Hobby 플랜에서 30개 이상, 상위 유료 플랜에서는 110개 이상의 AWS 서비스를 지원하는데요. 하지만 올해 3월부터는 최신 버전을 실행하려면 계정과 인증 토큰이 필요해졌고, 회사에서 쓰려면 유료 플랜이 필요합니다. 그래서 로컬에서 바로 실행할 수 있는 대안들이 잇따라 나왔습니다. MiniStack은 RDS나 ElastiCache를 만들면 실제 Postgres나 Redis 컨테이너를 띄워 앱이 직접 연결할 수 있게 했습니다. Floci는 AWS 서비스 20여 개로 시작해 119개까지 늘리고 Azure, GCP, OCI로도 범위를 넓혔습니다. Go로 만든 kumo는 AWS 서비스 80여 개를 바이너리 하나로 가볍게 실행할 수 있게 했고요. 다만 지원하는 서비스가 늘어날수록, 실제 AWS가 바뀔 때마다 에뮬레이터도 여전히 같은 방식으로 동작하는지 확인하는 일이 커집니다.

그러던 중에, 드디어 AWS가 자체 에뮬레이터를 공개했습니다.

Amazon의 개발기 〈How we built the agents that built AWS Emulator〉에 따르면, 자율 AI 에이전트들이 AWS API 모델을 명세로 삼고, 실제 AWS에서 어떻게 동작하는지 확인하며 에뮬레이터 코드를 작성했습니다. 이 과정에서 수만 개의 테스트가 쌓였고, AWS는 릴리스마다 서비스별 통과 건수를 공개합니다.

에뮬레이터 코드와 동작 일치도 테스트가 공개됐으니 다른 팀도 이를 바탕으로 AWS 호환 도구를 만들 수 있겠죠. 제가 더 흥미롭게 본 건 AWS가 운영해 온 서비스 자체를 에이전트가 따라야 할 기준으로 삼았다는 점입니다. 서비스가 바뀌면 실제 AWS에 요청을 보내 새 동작을 확인하고, 그 결과를 테스트에 추가할 수 있습니다. 방대한 AWS 생태계를 재현하는 일도 그렇게 확인할 수 있는 동작 하나씩 나눠 맡길 수 있었던 것 같습니다.

AWS를 쓰는 팀이라면 개발할 때 자주 돌리는 테스트 하나부터 에뮬레이터에서 실행해볼 만합니다. 코드가 바뀔 때마다 로컬이나 CI에서 확인하고, 배포 환경의 IAM 권한은 실제 AWS에서 검증하면 됩니다. 〈AWS Emulator의 제한사항〉을 보면 우리 팀의 테스트 중 어디까지 로컬로 가져올 수 있을지 가늠할 수 있습니다.

요즘 위클리에서도 새 AI 모델 소식이나 에이전트가 어디까지 할 수 있는지를 자주 이야기했는데요. 이번에는 AI를 써서 많은 개발자가 실제로 쓸 만한 도구를 만들었다는 이야기를 소개할 수 있어서 반가웠습니다. 앞으로도 이렇게 AI의 도움을 받아 누군가의 오래된 불편을 덜어주는 프로젝트를 더 자주 만나면 좋겠습니다.
