F-Algebras 해설 5/8 · foldr의 두 인자는 리스트의 어느 자리에 들어갈까요?

해설 대상 원문 · F-Algebras 원문 열기

검토일 · 2026-11-27

앞 편에서는 자연수의 한 층 NatF를 접었습니다. 그 층에는 자식 자리가 하나뿐이었고, 대수는 시작값 z와 한 걸음 함수 s를 정했습니다. 이 편은 원문의 「Folds」 절을 읽습니다. 리스트의 한 층에는 꼬리 자리 외에 원소 자리가 하나 더 있습니다. 그래서 한 걸음 함수는 원소도 함께 받아야 합니다. 이 편에서는 리스트 대수의 두 갈래가 foldr의 두 인자와 어떻게 대응하는지 확인합니다. 또 두 인자가 리스트의 어느 자리에 들어가는지 확인합니다. 끝에서는 원문의 결론 “foldr is just a convenient specialization of a catamorphism to lists”를 이 대응으로 읽습니다.

리스트 한 층: 원소 자리와 꼬리 자리

원문은 리스트 함자를 다음과 같이 정의합니다.

data ListF e a = NilF | ConsF e a

타입 매개변수는 두 개입니다. e는 원소(element)의 타입입니다. a는 재귀가 일어나는 자리, 곧 꼬리(tail)의 자리입니다. NatF와 비교하면 NilF는 ZeroF처럼 자식이 없는 갈래입니다. ConsF e a는 SuccF a에 원소 하나를 더한 갈래입니다.

원문은 a 자리에 재귀의 결과 List e를 넣어 data List e = Nil | Cons e (List e)를 얻습니다. 같은 재귀를 앞 편의 Fix로 쓰면 Fix (ListF e)입니다. Haskell에서 List e, Fix (ListF e), 내장 리스트 [e]는 각각 따로 선언된 타입입니다. 그러나 생성자는 서로 대응합니다 (Haskell 2010 4장). 이 편의 예인 [2,5]는 다음과 같이 쓸 수 있습니다.

리스트 Fix (ListF Int)
[] Fix NilF
[5] Fix (ConsF 5 (Fix NilF))
[2,5] Fix (ConsF 2 (Fix (ConsF 5 (Fix NilF))))

아래에서는 이 세 값을 차례로 nil, l5, l25라고 부릅니다. l25의 바깥 층에는 원소 2와 꼬리 l5가 들어 있습니다.

cata를 쓰려면 이 함자에도 Functor 인스턴스가 필요합니다. 원문의 이 절에는 인스턴스가 없습니다. 예제를 실행하려면 다음 인스턴스를 함께 적어야 합니다.

instance Functor (ListF e) where
  fmap _ NilF        = NilF
  fmap h (ConsF e x) = ConsF e (h x)

인스턴스의 대상은 ListF가 아니라 e를 고정한 ListF e입니다. Haskell의 Functor는 매개변수 하나를 받는 타입 생성자에 대해 정의됩니다. 따라서 fmap은 마지막 매개변수 a에만 작용합니다. 그 결과 fmap h는 꼬리 자리만 바꾸고 원소 e는 그대로 둡니다. 원문이 재귀 자리를 마지막 매개변수로 둔 데에는 이런 이유가 있습니다.

리스트 대수가 정하는 두 가지

리스트 대수는 운반체(carrier) a와 함수 alg :: ListF e a -> a의 쌍입니다. 원문에 따르면 이 함수는 두 생성자에 대해 패턴 매칭을 합니다. NilF에서의 값은 빈 리스트를 평가하는 방법입니다. ConsF에서의 값은 “current element”와 “previously accumulated value”를 결합하는 방법입니다. 두 값에 이름을 붙이면 다음과 같습니다.

z     = alg NilF          -- z :: a
k e r = alg (ConsF e r)   -- k :: e -> a -> a

반대로 z와 k가 주어지면 alg NilF = z, alg (ConsF e r) = k e r로 대수를 다시 만들 수 있습니다. 따라서 리스트 대수 하나를 정하는 일은 z와 k를 정하는 일과 같습니다. NatF의 s는 이전 결과 하나만 받았습니다. 그러나 k는 현재 원소 e도 함께 받습니다.

‘앞서 누적한 값’이라는 표현은 주의해서 읽어야 합니다. cata에서 r 자리에 들어가는 값은 꼬리를 접은 결과입니다. l25의 바깥 층에서 r은 [5]를 접은 결과입니다. 꼬리 [5]를 접는 식은 k 5 z입니다. 따라서 이 값은 왼쪽부터 원소를 하나씩 더해 가는 누적값이 아닙니다. 결과의 괄호 구조로 보면 맨 앞 원소에 적용하는 k가 가장 바깥에 있습니다. 꼬리를 접는 식은 그 k의 둘째 인자 안에 들어갑니다. 그 식을 실제로 계산할지는 k가 정합니다. 뒤에서 볼 foldr로 예를 들면, 둘째 인자를 버리는 const에서는 foldr const 0 (2 : undefined) = const 2 (foldr const 0 undefined) = 2입니다. 이 경우 꼬리는 열리지 않습니다.

길이 대수로 [2,5]를 접기

원문의 첫 예는 길이를 구하는 대수입니다. 이 대수의 운반체는 Int입니다.

lenAlg :: ListF e Int -> Int
lenAlg (ConsF e n) = n + 1
lenAlg NilF = 0

앞 편의 정의 cata alg = alg . fmap (cata alg) . unFix를 손으로 펼쳐 보겠습니다. 각 줄에서는 unFix를 이미 적용한 상태로 적었습니다.

cata lenAlg nil = lenAlg (fmap (cata lenAlg) NilF)
                = lenAlg NilF
                = 0
cata lenAlg l5  = lenAlg (fmap (cata lenAlg) (ConsF 5 nil))
                = lenAlg (ConsF 5 0)
                = 1
cata lenAlg l25 = lenAlg (fmap (cata lenAlg) (ConsF 2 l5))
                = lenAlg (ConsF 2 1)
                = 2

마지막 계산의 중간 값 ConsF 2 1이 이 과정의 중심입니다. 이 값의 타입은 ListF Int Int입니다. 두 숫자는 모두 Int이지만 역할이 서로 다릅니다. 2는 원소이며 fmap을 거친 뒤에도 그대로 남아 있습니다. 1은 꼬리 [5]의 길이입니다. 이 값은 fmap (cata lenAlg)가 l5 자리에 넣은 것입니다. lenAlg는 원소를 사용하지 않으므로 서명의 e는 어떤 타입이어도 됩니다.

원문의 “The type of the value and the type of the accumulator are given by the carrier type.”도 이 예로 읽을 수 있습니다. 최종 결과와 r 자리의 누적값은 모두 운반체 Int의 값입니다. 원소의 타입 e는 운반체와 별개입니다.

foldr의 두 인자를 리스트에 겹쳐 보기

원문은 이 대수를 Haskell의 전통적인 정의와 비교합니다. 원문에는 아래의 첫 줄인 서명이 없습니다. 서명 없이 둘째 줄만 정의하면 Haskell 2010의 단형성 제한(monomorphism restriction)과 기본 타입(default) 규칙이 적용됩니다. 그 결과 타입은 [e] -> Integer가 됩니다 (Haskell 2010 4장). lenAlg와 같은 운반체로 비교하기 위해 서명을 함께 적습니다.

length :: [e] -> Int
length = foldr (\e n -> n + 1) 0

Haskell 2010의 foldr는 다음과 같습니다. 여기서는 인자 이름을 이 편의 k, z로 바꾸었습니다. 타입 변수 이름도 e, r로 바꾸었습니다.

foldr :: (e -> r -> r) -> r -> [e] -> r
foldr k z []     = z
foldr k z (x:xs) = k x (foldr k z xs)

Haskell 2010은 이 서명을 (a -> b -> b) -> b -> [a] -> b로 적습니다. 그러나 순서는 같습니다. 첫 타입 변수는 원소 타입이고, 둘째 타입 변수는 결과 타입입니다. 앞 절의 운반체 a를 여기서는 r로 적습니다. 이름을 맞추면 ListF e r에서 e가 원소이고 r이 꼬리를 접은 결과라는 대응이 k :: e -> r -> r에 그대로 보입니다.

이 정의를 [2,5], 곧 2 : (5 : [])에 펼치면 두 인자의 자리가 드러납니다.

2 : (5 : [])
k 2 (k 5 z)

z는 리스트 끝의 [] 자리에 들어갑니다. k는 각 (:) 자리에 들어갑니다. 결과의 괄호 구조는 리스트의 구조와 같습니다. Haskell 2010도 foldr를 리스트 [x1, x2, ..., xn]을 오른쪽부터 결합해 f x1 (f x2 (... (f xn z))) 모양의 값을 만드는 함수로 설명합니다 (Haskell 2010 Data.List).

길이의 경우 k = \e n -> n + 1, z = 0입니다. 따라서 k 2 (k 5 0) = k 2 1 = 2입니다. 안쪽의 k 5 0 = 1은 cata 계산의 lenAlg (ConsF 5 0) = 1과 같은 단계입니다.

대수의 갈래 foldr의 인자 리스트에서 들어가는 자리
lenAlg NilF = 0 z = 0 끝의 []
lenAlg (ConsF e n) = n + 1 k = \e n -> n + 1 각 (:)

원문의 “The two arguments to foldr are exactly the two components of the algebra.”는 이 표의 내용을 말합니다.

합계 대수: 원소를 실제로 쓰는 경우

원문의 둘째 예는 원소를 결과에 반영하는 대수입니다.

sumAlg :: ListF Double Double -> Double
sumAlg (ConsF e s) = e + s
sumAlg NilF = 0.0

[2.0,5.0]을 같은 방식으로 접으면 각 층에서 다음 값을 얻습니다.

빈 꼬리:   sumAlg NilF            = 0.0
[5.0]:     sumAlg (ConsF 5.0 0.0) = 5.0 + 0.0 = 5.0
[2.0,5.0]: sumAlg (ConsF 2.0 5.0) = 2.0 + 5.0 = 7.0

이 대수에서는 원소 타입과 운반체가 모두 Double입니다. ConsF 2.0 5.0에서 2.0은 원소이고 5.0은 꼬리의 합입니다. 이 계산을 foldr (\e s -> e + s) 0.0으로 쓰면 k 2.0 (k 5.0 0.0) = 2.0 + (5.0 + 0.0)입니다. foldr는 리스트의 구조를 그대로 따르므로 괄호가 오른쪽에 모입니다.

원문의 sum은 비교를 위해 저자가 적은 정의입니다. Haskell 2010 Prelude는 sum = foldl (+) 0으로 정의합니다. 이 정의는 ((0 + x1) + x2) + ...처럼 왼쪽부터 결합합니다 (Haskell 2010 Prelude). 부동소수점 덧셈은 반올림 때문에 결합 순서에 따라 결과가 달라질 수 있습니다. 따라서 두 정의가 모든 입력에서 같은 값을 낸다고 읽을 수는 없습니다. Haskell 2010은 Double의 표현 방식도 고정하지 않습니다 (Haskell 2010 6장). 이 편에서 예로 든 [2.0,5.0]에서는 중간 합 5.0과 결과 7.0이 모두 정확하므로 이 문제가 생기지 않습니다.

foldr는 리스트에 특수화한 cata입니다

원문의 마지막 문장은 “foldr is just a convenient specialization of a catamorphism to lists”입니다. 여기서 ‘특수화(specialization)’는 cata의 함자 f를 ListF e로 고정한다는 뜻입니다. 이렇게 고정하면 대수는 z와 k의 쌍과 같아집니다. 따라서 대수 하나를 받는 함수를 두 인자를 받는 함수로 다시 쓸 수 있습니다.

foldrC :: (e -> r -> r) -> r -> Fix (ListF e) -> r
foldrC k z = cata alg
  where
    alg NilF        = z
    alg (ConsF e r) = k e r

원문의 대수처럼 바깥 생성자를 패턴 매칭하는 대수에서는 반대 방향도 성립합니다. 이때 cata alg는 foldrC (\e r -> alg (ConsF e r)) (alg NilF)와 같습니다. foldrC는 이 편에서 설명을 위해 붙인 이름입니다. 여기서 비교하는 Haskell 2010의 foldr는 Fix (ListF e)가 아니라 내장 리스트 [e]를 받습니다. 현재 GHC의 Prelude.foldr는 Foldable 클래스에 대해 정의되므로, GHCi에서 보이는 서명은 이보다 더 일반적입니다. 두 타입은 따로 선언한 타입이지만, NilF는 []와 대응하고 ConsF는 (:)와 대응합니다. 두 타입 사이의 변환 함수도 접기로 쓸 수 있습니다. Fix (ListF e)에서 [e]로 갈 때는 foldrC (:) []를 씁니다. 반대로 갈 때는 foldr (\e r -> Fix (ConsF e r)) (Fix NilF)를 씁니다. 두 경우 모두 각 생성자 자리에 상대 타입의 생성자를 넣습니다. 원문의 ‘convenient’는 Fix 포장이나 대수 자료형 없이 두 갈래를 인자로 바로 넘길 수 있다는 뜻으로 읽을 수 있습니다.

원문의 첫 문장 “A list of e is the initial algebra of the following functor”도 이 대응으로 읽을 수 있습니다. 리스트를 운반체로 하는 구조 사상은 NilF를 []로 보내고 ConsF x xs를 x : xs로 보내는 함수입니다.

inList :: ListF e [e] -> [e]
inList NilF         = []
inList (ConsF x xs) = x : xs

앞 편의 준동형 조건 h . inList = alg . fmap h를 두 갈래에 적용하면 다음 두 식이 나옵니다.

h []     = z
h (x:xs) = k x (h xs)

두 식은 h가 두 생성자를 보존한다는 뜻입니다. 유한하고 완전히 정의된 리스트에서 두 식을 만족하는 h는 foldr k z 하나뿐입니다. 증명은 리스트 길이에 대한 귀납이며, 앞 편의 자연수 논증과 같습니다. 따라서 운반체를 [e]의 값 가운데 유한하고 완전히 정의된 리스트들의 집합으로 제한하면, 임의의 k와 z에 대해 이런 함수가 하나씩 정해집니다. 이 제한된 운반체와 inList의 쌍을 초기 대수라고 부를 수 있습니다. 원문의 마지막 문장에 나오는 foldr가 바로 그 유일한 함수입니다. Hutton은 이 성질을 접기의 보편 성질(universal property)이라고 부릅니다. 그리고 이 성질을 어떤 함수가 foldr로 표현된다는 사실을 보이는 도구로 사용합니다 (Hutton의 1999년 튜토리얼).

원문의 length로 확인해 보겠습니다. Haskell 2010 Prelude는 length를 length [] = 0과 length (_:l) = 1 + length l로 정의합니다 (Haskell 2010 Prelude). k = \e n -> n + 1, z = 0으로 두면 Prelude의 length는 위의 두 식을 만족합니다. 따라서 유한 리스트에서는 서명을 붙인 원문의 length와 Prelude의 length가 같습니다.

다만 이 귀납은 유한 리스트에만 적용됩니다. Haskell의 리스트에는 [1..] 같은 무한 리스트도 있습니다. k가 둘째 인자를 사용하지 않으면 꼬리를 접지 않아도 됩니다. 예를 들어 foldr (\e _ -> e) 0 [1..]에서는 첫 원소 1이 그대로 결과가 됩니다. 이때 결과가 나오는지는 첫 원소에서 k가 값을 낼 수 있는지에 따라 달라집니다. 둘째 인자를 사용하더라도 결과의 일부를 먼저 내놓을 수 있습니다. foldr (:) [] [1..] = 1 : foldr (:) [] [2..]이므로 take 1을 적용한 결과는 [1]입니다. 반면 길이 대수에서는 n + 1의 정숫값을 내려면 n의 값이 필요합니다. 그래서 foldr (\e n -> n + 1) 0 [1..]의 계산은 끝나지 않습니다. 이것은 앞 편에서 본 cata의 지연 평가와 같은 현상입니다.

다음 질문: 씨앗에서 한 층 만들기

cata는 이미 있는 리스트를 소비합니다. unFix가 바깥 층을 엽니다. 다음으로 fmap이 꼬리 자리에 꼬리를 접는 식을 놓고, 대수가 그 층을 결합합니다. 원문의 다음 절은 이 화살표의 방향을 뒤집습니다. 이번에는 한 층을 결합하는 f a -> a 대신 a -> f a 모양의 함수를 씁니다. 이 함수는 씨앗(seed) 하나에서 한 층을 만듭니다. 리스트에서 그 층이 NilF이면 생성은 거기서 끝납니다. 그 층이 ConsF x next이면 원소 x를 내놓고 다음 씨앗 next에서 생성을 이어 갑니다. 예를 들어 씨앗 3에서는 ConsF 3 2를 만들고, 씨앗 0에서는 NilF를 만들 수 있습니다. 스트림의 한 층에는 끝내는 갈래가 없으므로 언제나 다음 씨앗이 하나 있습니다. 다음 편의 질문은 이런 한 걸음 함수를 반복하여 리스트나 스트림 전체를 만드는 방법은 무엇이고, 이 반복이 어떤 구조에 도착하는가입니다.

이 편의 원문

Folds

A list of e is the initial algebra of the following functor:

data ListF e a = NilF | ConsF e a

Indeed, replacing the variable a with the result of recursion, which we’ll call List e, we get:

data List e = Nil | Cons e (List e)

An algebra for a list functor picks a particular carrier type and defines a function that does pattern matching on the two constructors. Its value for NilF tells us how to evaluate an empty list, and its value for ConsF tells us how to combine the current element with the previously accumulated value.

For instance, here’s an algebra that can be used to calculate the length of a list (the carrier type is Int):

lenAlg :: ListF e Int -> Int
lenAlg (ConsF e n) = n + 1
lenAlg NilF = 0

Indeed, the resulting catamorphism cata lenAlg calculates the length of a list. Notice that the evaluator is a combination of (1) a function that takes a list element and an accumulator and returns a new accumulator, and (2) a starting value, here zero. The type of the value and the type of the accumulator are given by the carrier type.

Compare this to the traditional Haskell definition:

length = foldr (\e n -> n + 1) 0

The two arguments to foldr are exactly the two components of the algebra.

Let’s try another example:

sumAlg :: ListF Double Double -> Double
sumAlg (ConsF e s) = e + s
sumAlg NilF = 0.0

Again, compare this with:

sum = foldr (\e s -> e + s) 0.0

As you can see, foldr is just a convenient specialization of a catamorphism to lists.
