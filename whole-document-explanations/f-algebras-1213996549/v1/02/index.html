F-Algebras 해설 2/8 · RingF 한 층에서 깊이 제한이 없는 식 트리로

해설 대상 원문 · F-Algebras 원문 열기

검토일 · 2026-11-27

앞 편은 RMul (RAdd 1 1) (RNeg 1)이라는 값에서 멈췄습니다. 이 값의 타입은 RingF (RingF Integer)입니다. 한 층만 받는 evalZ :: RingF Integer -> Integer는 이 값에 바로 적용할 수 없습니다. 원문의 Recursion 절은 이 문제에 두 단계로 답합니다. 먼저 자식 자리에 자기 자신을 넣은 재귀 자료형 Expr를 씁니다. 다음으로 RingF를 한 겹씩 쌓아 깊이가 정해진 트리를 만들고, 그 과정을 끝없이 이어 고정점(fixed point) Fix를 얻습니다. 이 절은 Fix와 unFix가 서로의 역이라는 문장에서 끝납니다. 원문은 그다음부터 「Category of F-Algebras」 절에서 같은 함자 위의 대수들을 범주로 모읍니다. 이 편의 마지막 단락은 그 절의 첫 질문을 다룹니다. 이 편은 같은 교육용 식 (1+1)×(−1)을 세 가지 표현으로 따라갑니다.

자식 자리에 Expr 자신을 넣기

RingF a에서 a는 피연산자 자리입니다. 저자는 이 자리를 지금 정의하는 타입 자신으로 바꿉니다.

data Expr = RZero
          | ROne
          | RAdd Expr Expr
          | RMul Expr Expr
          | RNeg Expr

이제 RMul의 두 자식은 Integer가 아니라 다시 Expr입니다. 대신 정수 리터럴을 넣을 자리가 사라집니다. 잎에 올 수 있는 것은 인자가 없는 RZero와 ROne뿐입니다. 그래서 교육용 식은 다음처럼 써야 합니다.

e :: Expr
e = RMul (RAdd ROne ROne) (RNeg ROne)

원문의 재귀 평가기는 각 갈래에서 자식에게 먼저 evalZ를 적용합니다. 손으로 펼치면 다음과 같습니다.

evalZ (RMul (RAdd ROne ROne) (RNeg ROne))
= evalZ (RAdd ROne ROne) * evalZ (RNeg ROne)
= (evalZ ROne + evalZ ROne) * (-(evalZ ROne))
= (1 + 1) * (-1)
= -2

저자는 이 표현이 ‘모든 정수를 1의 합으로 나타내게 한다’고 말합니다. 이 말은 축약입니다. 원문이 지적하는 불편은 임의의 정수 리터럴을 담는 생성자가 없다는 점입니다. 정수는 상수와 연산을 조합해 만들어야 합니다. 3은 ROne 세 개를 더한 RAdd ROne (RAdd ROne ROne)이고, 0은 RZero, -1은 RNeg ROne입니다. 이 불편은 표현의 문제입니다. 저자가 다음 문단에서 던지는 질문은 다른 곳에 있습니다. 이 재귀 평가기에는 한 층의 해석(0, 1, +, *, 부호 반전)과 자식 방문이 한 함수 안에 섞여 있습니다. 앞 편의 F-대수는 한 층의 해석만 담았습니다. 저자는 이 둘을 나누어 Expr도 F-대수의 언어로 설명하려고 합니다.

한 겹씩 쌓은 타입: RingF1, RingF2

저자의 첫 시도는 RingF를 여러 번 적용하는 것입니다.

type RingF1 a = RingF (RingF a)
type RingF2 a = RingF (RingF (RingF a))

저자는 RingF a 하나를 깊이 0인 트리로 셉니다. 그러면 RingF1 a는 깊이 1, RingF2 a는 깊이 2입니다. a 자리는 아직 채워지지 않은 구멍(hole)입니다.

앞 편에서 막힌 값이 바로 RingF1 Integer입니다. 바깥 RMul이 바깥 층이고, RAdd 1 1과 RNeg 1이 안쪽 층이며, 정수 1들이 구멍을 채웠습니다. 이 값은 두 단계로 평가합니다. 여기서 쓰는 evalZ는 바로 앞의 재귀 함수 Expr -> Integer가 아닙니다. 앞 편에서 정의한 한 층 평가기 evalZ :: RingF Integer -> Integer입니다. 원문은 두 예에서 함수 이름과 생성자 이름을 모두 재사용하므로, 두 정의는 따로 읽어야 합니다. 또한 fmap을 쓰려면 RingF가 Functor 인스턴스를 가져야 합니다. 원문의 data RingF a 선언만으로는 인스턴스가 생기지 않습니다. 이 편의 예는 DeriveFunctor 확장을 켜고 RingF 선언에 deriving Functor를 붙였다고 전제합니다 (GHC 사용자 안내서).

먼저 fmap evalZ로 안쪽 층을 평가합니다. fmap은 바깥 생성자를 그대로 두고 피연산자 자리에만 함수를 적용합니다.

fmap evalZ (RMul (RAdd 1 1) (RNeg 1))
= RMul (evalZ (RAdd 1 1)) (evalZ (RNeg 1))
= RMul 2 (-1)                 -- :: RingF Integer

evalZ (RMul 2 (-1)) = -2

따라서 evalZ . fmap evalZ :: RingF1 Integer -> Integer입니다. 재귀 Expr 평가기와 같은 -2가 나옵니다. 깊이 2에서는 evalZ . fmap (evalZ . fmap evalZ)가 필요합니다. 한 층 평가기 evalZ는 그대로 다시 쓰지만, 깊이마다 타입과 조립한 함수가 달라집니다. 깊이를 미리 정할 수 없는 식에는 이 방법을 쓸 수 없습니다.

이 타입들에는 주의할 점이 하나 있습니다. 상수 RZero와 ROne은 어느 층에서나 가지를 끝낼 수 있습니다. 예를 들어 ROne :: RingF1 Integer는 바깥 생성자에서 바로 끝나며 안쪽 층을 쓰지 않습니다. 반면 a 값은 RingFn a에서 RingF 층을 정확히 n+1개 지난 자리에만 올 수 있습니다. RNeg (1 :: Integer)는 RingF Integer에 들어가지만, 같은 값을 RingF1 Integer 자리에 쓰면 타입 오류가 납니다. 그 자리에서 RNeg의 피연산자는 Integer가 아니라 RingF Integer여야 하기 때문입니다. 그러므로 RingFn a는 깊이가 정확히 n인 트리가 아니라 깊이가 n을 넘지 않는 트리입니다. 원문의 기호식 RingF(n+1) a = RingF (RingFn a)는 한 층을 더 얹는 규칙입니다. 원문에서 n과 n+1은 아래첨자입니다. Haskell은 이런 타입 수준의 n을 이 형태로 허용하지 않으므로, 이 식은 기호로만 읽어야 합니다.

Expr는 왜 a에 의존하지 않을까요?

저자는 이 과정을 무한히 반복하면 Expr에 도착한다고 말합니다. 그리고 Expr에는 a가 없다는 점을 짚습니다. 저자는 이 설명을 손짓 논증(hand-waving argument)이라고 부르고, 나중에 엄밀히 하겠다고 말합니다. 여기서는 이 직관이 정확히 성립하는 경우를 하나 살펴봅니다. 아래 표와 논증은 이 설명을 위해 구성한 것입니다.

시작점으로 빈 타입, 곧 집합 범주 Set의 빈집합 ∅를 택합니다. ∅에는 원소가 없으므로 RAdd, RMul, RNeg의 피연산자를 채울 수 없습니다. 따라서 RingF ∅에는 RZero와 ROne 두 값만 있습니다. 다음 단계 RingF (RingF ∅)에서는 이 두 값을 피연산자로 쓸 수 있습니다.

단계 처음 나타나는 예
∅ 없음
RingF ∅ RZero, ROne
RingF (RingF ∅) RAdd ROne ROne, RNeg ROne
RingF (RingF (RingF ∅)) RMul (RAdd ROne ROne) (RNeg ROne)

교육용 식 e는 세 번째 단계에서 처음 나타납니다. 구멍이 없으므로 모든 값이 닫힌 식(closed expression)입니다. 앞 단계의 식은 다음 단계에도 그대로 들어 있습니다. 상수는 어느 단계에서나 만들 수 있고, 다른 생성자의 식은 자식들이 앞 단계에 있으면 만들 수 있기 때문입니다. 잎의 깊이를 0으로 세면 깊이가 d인 식은 d+1번째 단계에서 처음 나타납니다. 그러므로 모든 유한한 Expr 값은 어떤 유한 단계에 있습니다. ‘무한히 반복한다’는 말은 무한한 트리를 만든다는 뜻이 아닙니다. 단계에 상한이 없으므로 모든 유한 깊이를 담는다는 뜻입니다.

한 층을 더 적용해도 달라지지 않는 이유는 다음 왕복으로 볼 수 있습니다. 유한한 닫힌 식 전체를 T라고 놓습니다. RingF T의 값 하나, 예를 들어 RMul t1 t2는 생성자 하나와 T의 자식들입니다. 자식들을 새 뿌리 RMul 아래에 붙여도 트리는 여전히 유한하므로 T의 식이 됩니다. 반대로 T의 식을 뿌리에서 한 번 열면, 뿌리 생성자와 유한한 자식들이 남으므로 다시 RingF T의 값입니다. 교육용 식 e를 열면 RMul (RAdd ROne ROne) (RNeg ROne)의 뿌리 RMul과 두 자식이 나오고, 다시 붙이면 e로 돌아갑니다. 이 두 방향이 서로를 되돌리므로 RingF T ≅ T입니다. 이 동형에는 a가 없습니다. 이 예에서 a가 사라지는 이유가 이것입니다. 저자의 후속 글은 이 구성을 빈집합에 해당하는 초기 대상(initial object)에서 출발하는 사슬과 그 쌍대극한(colimit)으로 정식화합니다. 저자의 후속 구성

‘시작점은 중요하지 않다’는 문장은 더 좁게 읽어야 합니다. 위의 왕복은 빈집합에서 시작한 닫힌 식에 대한 것이며, 임의의 시작점에서 같은 곳으로 수렴한다는 것까지 보이지는 않습니다. a = Integer에서 시작하면 유한 단계의 값은 언제나 정수 잎을 가질 수 있습니다. 저자도 임의의 범주와 임의의 자기함자에서는 이 결론이 늘 참이 아니라고 덧붙입니다. Set 안에서도 모든 함자가 이렇게 수렴하지는 않으며, 반례는 뒤 편에서 다룹니다. 이 예가 보이는 것은 RingF처럼 갈래 수와 인자 수가 유한한 함자의 경우입니다. 쌍대극한 구성의 조건

고정점 Fix: 한 층을 감싸는 생성자

f를 무한히 적용한 결과에 f를 한 번 더 적용해도 달라지지 않는다는 직관을 식으로 쓰면 다음과 같습니다.

Fix f = f (Fix f)

Haskell은 이 등식을 동형으로 구현합니다.

newtype Fix f = Fix (f (Fix f))

왼쪽 Fix는 타입 생성자입니다. 함자 f를 받아 타입을 만듭니다. 오른쪽 Fix는 값 생성자입니다. 저자가 제안한 대로 newtype Fix f = In (f (Fix f))로 바꾸어 읽으면, 값 생성자가 f (Fix f) 한 층을 받아 Fix f 안으로 넣는(in) 함수라는 점이 드러납니다. 원문은 관례에 따라 Fix라는 이름을 그대로 씁니다.

값 생성자의 타입은 newtype 선언이 이미 정합니다. 따로 선언하는 시그니처가 아니며, GHCi의 :t Fix 질의로 확인할 수 있는 정보입니다.

Fix :: f (Fix f) -> Fix f

반대 방향 함수는 직접 정의합니다.

unFix :: Fix f -> f (Fix f)
unFix (Fix x) = x

RingF에 적용하면 Fix RingF의 값은 각 층을 Fix로 감싼 트리입니다. 교육용 식은 다음과 같습니다.

one :: Fix RingF
one = Fix ROne

e' :: Fix RingF
e' = Fix (RMul (Fix (RAdd one one)) (Fix (RNeg one)))

Expr의 e와 비교하면 생성자마다 Fix가 하나씩 붙었을 뿐입니다. Expr의 ROne은 Fix ROne에, RAdd x y는 Fix (RAdd x' y')에 대응합니다. 여기서 x'와 y'는 자식을 같은 방법으로 옮긴 값입니다. 이 대응으로 Expr와 Fix RingF의 유한한 값이 하나씩 짝지어집니다. 피연산자 자리 a에는 다시 Fix RingF가 들어갑니다. 깊이마다 다른 타입이 필요했던 RingFn의 문제가 타입 하나로 해결됩니다.

unFix는 맨 바깥 Fix 하나만 벗깁니다.

unFix e' = RMul (Fix (RAdd one one)) (Fix (RNeg one))   -- :: RingF (Fix RingF)

결과는 바깥 RMul 한 층이고, 두 자식은 아직 감싸인 트리입니다. 정의에서 곧바로 임의의 층 x에 대해 unFix (Fix x) = x입니다. 반대 방향도 모든 값에서 성립합니다. Fix f의 값 t는 언제나 어떤 x에 대해 t = Fix x 꼴이므로 Fix (unFix t) = Fix x = t입니다. e'는 이 경우의 한 예입니다. 저자가 두 함수를 서로의 역(inverse)이라고 말하는 근거가 이 두 등식입니다. newtype 생성자는 값의 표현에 별도의 상자를 더하지 않으므로, 이 왕복은 데이터를 바꾸지 않습니다. Haskell 2010 §4.2.3

여기에는 경계가 하나 있습니다. x :: Fix RingF로 두고 x = Fix (RNeg x)라고 정의하면, 오른쪽도 Fix RingF 타입이므로 이 재귀 정의는 타입이 맞습니다. 타입 검사는 평가 방식과 관계없이 이 정의를 받아들입니다. 지연 평가가 하는 일은 실행 시에 나타납니다. case unFix x of RNeg _ -> True는 바깥 생성자 RNeg만 확인하고 자식 x를 계산하지 않으므로 True로 끝납니다. 그러나 이 값은 끝없이 RNeg가 이어지는 트리이며, 빈집합에서 구성한 Set의 예에는 없습니다. 앞 절의 구성과 이 편의 대응과 평가는 유한하고 완전히 정의된 식만 다룹니다.

Fix로 식 트리를 나타내는 방법은 Haskell에서 확장 가능한 식을 표현할 때도 쓰입니다. 이 표현에서 평가는 세 부분으로 나뉩니다. unFix로 한 층을 열고, 자식들을 평가하고, 그 층을 evalZ로 해석합니다. 저자가 ‘이 함수들은 나중에 쓴다’고 말하는 대목이 이 조립을 가리킵니다. 뒤의 편들이 이 조립을 정확한 정의로 만듭니다. 식 트리와 한 단계 평가

F-대수의 범주로

원문에서는 이 대목부터 「Category of F-Algebras」 절이 시작됩니다. 저자는 여기서 ‘가장 오래된 수법’을 꺼냅니다. 새로운 대상을 만드는 방법을 찾으면, 그 대상들이 범주를 이루는지 확인하는 것입니다. 자기함자 F를 고정하면, 대상(object)은 F-대수, 곧 운반체 a와 평가 함수 F a -> a의 쌍입니다. 둘 다 원래 범주 C에 속합니다.

사상은 대수 (a, f)에서 대수 (b, g)로 갑니다. 저자는 이 사상을 운반체 사이의 사상 m : a -> b로 정의합니다. 다만 아무 사상이나 되는 것은 아니고, 두 평가기와 맞아야 합니다. 이런 구조 보존 사상을 준동형사상(homomorphism)이라고 부릅니다. 조건을 쓰려면 m을 한 층 전체에 적용할 수 있어야 합니다. 원문이 마지막에 말하는 들어 올리기(lifting)가 이것입니다. 원문의 수학 기호로는 F m : F a → F b이고, Haskell에서는 fmap m이 이 역할을 합니다. 대문자 F는 수학 기호이며 예제에는 그 이름의 타입 생성자가 없습니다. 교육용으로 m = (*10) :: Integer -> Integer를 택하면 fmap m :: RingF Integer -> RingF Integer이고, 계산은 다음과 같습니다.

fmap (*10) (RAdd 2 3) = RAdd 20 30
fmap (*10) ROne       = ROne

들어 올린 사상은 생성자를 바꾸지 않고 피연산자만 옮깁니다. 이제 RingF Integer의 한 층에서 출발하는 두 경로가 생깁니다. 하나는 출발 대수의 평가기로 먼저 계산한 뒤 m으로 옮기는 경로입니다. 다른 하나는 fmap m으로 피연산자를 먼저 옮긴 뒤 도착 대수의 평가기로 계산하는 경로입니다. 두 대수가 모두 (Integer, evalZ)라면, RAdd 2 3에서 첫 경로는 5를 거쳐 50이고 둘째 경로는 RAdd 20 30을 거쳐 50입니다. 그러나 ROne에서는 첫 경로가 1을 거쳐 10이고, 둘째 경로는 ROne을 거쳐 1입니다. 따라서 (*10)은 이 대수에서 자기 자신으로 가는 준동형이 아닙니다. 두 경로가 모든 생성자에서 일치해야 한다는 조건을 도표로 어떻게 쓰는지가 다음 편의 질문입니다.

이 편의 원문

Recursion

One way to generate arbitrary expression trees is to replace the variable a inside the functor definition with recursion. For instance, an arbitrary expression in a ring is generated by this tree-like data structure:

data Expr = RZero
          | ROne
          | RAdd Expr Expr 
          | RMul Expr Expr
          | RNeg Expr

We can replace the original ring evaluator with its recursive version:

evalZ :: Expr -> Integer
evalZ RZero        = 0
evalZ ROne         = 1
evalZ (RAdd e1 e2) = evalZ e1 + evalZ e2
evalZ (RMul e1 e2) = evalZ e1 * evalZ e2
evalZ (RNeg e)     = -(evalZ e)

This is still not very practical, since we are forced to represent all integers as sums of ones, but it will do in a pinch.

But how can we describe expression trees using the language of F-algebras? We have to somehow formalize the process of replacing the free type variable in the definition of our functor, recursively, with the result of the replacement. Imagine doing this in steps. First, define a depth-one tree as:

type RingF1 a = RingF (RingF a)

We are filling the holes in the definition of RingF with depth-zero trees generated by RingF a. Depth-2 trees are similarly obtained as:

type RingF2 a = RingF (RingF (RingF a))

which we can also write as:

type RingF2 a = RingF (RingF1 a)

Continuing this process, we can write a symbolic equation:

type RingFn+1 a = RingF (RingFn a)

Conceptually, after repeating this process infinitely many times, we end up with our Expr. Notice that Expr does not depend on a. The starting point of our journey doesn’t matter, we always end up in the same place. This is not always true for an arbitrary endofunctor in an arbitrary category, but in the category Set things are nice.

Of course, this is a hand-waving argument, and I’ll make it more rigorous later.

Applying an endofunctor infinitely many times produces a fixed point, an object defined as:

Fix f = f (Fix f)

The intuition behind this definition is that, since we applied f infinitely many times to get Fix f, applying it one more time doesn’t change anything. In Haskell, the definition of a fixed point is:

newtype Fix f = Fix (f (Fix f))

Arguably, this would be more readable if the constructor’s name were different than the name of the type being defined, as in:

newtype Fix f = In (f (Fix f))

but I’ll stick with the accepted notation. The constructor Fix (or In, if you prefer) can be seen as a function:

Fix :: f (Fix f) -> Fix f

There is also a function that peels off one level of functor application:

unFix :: Fix f -> f (Fix f)
unFix (Fix x) = x

The two functions are the inverse of each other. We’ll use these functions later.

Here’s the oldest trick in the book: Whenever you come up with a way of constructing some new objects, see if they form a category. Not surprisingly, algebras over a given endofunctor F form a category. Objects in that category are algebras — pairs consisting of a carrier object a and a morphism F a -> a, both from the original category C.

To complete the picture, we have to define morphisms in the category of F-algebras. A morphism must map one algebra (a, f) to another algebra (b, g). We’ll define it as a morphism m that maps the carriers — it goes from a to b in the original category. Not any morphism will do: we want it to be compatible with the two evaluators.
