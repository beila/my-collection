해설 대상 원문 · F-Algebras 원문 열기

검토일 · 2026-11-27

앞 편의 StreamF 한 층에는 끝내는 갈래가 없었습니다. 그래서 처음 몇 개의 소수만 원할 때는 쌍대대수가 아니라 관찰하는 쪽이 take로 멈춰야 했습니다. 이 편은 원문 「Coalgebras」 절의 나머지 문단을 읽습니다. 여기에는 두 예가 나옵니다. 첫째 예는 리스트를 펼치는 unfoldr입니다. 이 예에서는 한 층에 ‘여기서 끝’이라는 갈래가 더해집니다. 둘째 예는 렌즈(lens)입니다. 이 예에서는 다음 상태가 하나로 정해지지 않고, 써 넣을 수 있는 값마다 하나씩 있습니다. 두 예 모두 앞 편의 질문으로 읽습니다. 씨앗은 무엇이고, 한 층에서 무엇을 관찰할까요? 앞 편에서 약속한 대로 unfoldr, Maybe, get, set, Store의 도표도 그립니다.

Maybe 쌍: 끝낼 수 있는 한 층

원문은 unfoldr의 타입을 다음과 같이 적습니다.

unfoldr :: (b -> Maybe (a, b)) -> b -> [a]

첫 인자가 쌍대대수입니다. 이 편에서는 이 인자를 step이라고 부릅니다. 운반체는 씨앗 타입 b이고, 한 층의 모양은 다음 함자 L이 정합니다.

L X = Maybe (a, X)

Just (x, b')는 원소 x 하나를 내고 다음 씨앗 b'을 남긴다는 뜻입니다. 이 부분은 StreamF x b'와 같습니다. 새로 생긴 것은 Nothing입니다. 원문의 “the functor is modified to produce a Maybe pair”는 이 갈래를 더했다는 뜻입니다. StreamF a X를 집합으로 쓰면 a × X였고, L X는 1 + a × X입니다. 이것은 앞 편들의 ListF a X와 같은 모양입니다. Nothing은 NilF에 대응하고, Just (x, b')는 ConsF x b'에 대응합니다.

함자 L의 fmap은 자식 자리, 곧 다음 씨앗에만 작용합니다. 이 편에서는 이 함수를 fmapL로 적습니다. fmapL은 완전히 정의된 값만 다루는 집합 모형에서 쓰는 함수입니다.

fmapL :: (b -> c) -> Maybe (a, b) -> Maybe (a, c)
fmapL h Nothing        = Nothing
fmapL h (Just (x, b')) = Just (x, h b')

Just 안의 쌍이 정의된 값이면 Haskell의 fmap (fmap h)도 같은 결과를 냅니다. 바깥 fmap은 Maybe 안으로 들어가고, 안쪽 fmap은 쌍의 둘째 성분에 작용합니다. 원소 x는 그대로 남습니다. 다만 Just undefined에서는 두 함수가 다릅니다. fmapL은 안쪽 쌍을 패턴 매칭하므로 바깥 생성자만 요구해도 실패합니다. 중첩 fmap은 쌍을 열기 전에 바깥 Just를 내놓습니다. 같은 이유로 Haskell 값 전체에서는 fmapL이 함자의 항등 법칙도 지키지 않습니다. id (Just undefined)는 바깥 Just를 보존하지만, fmapL id (Just undefined)는 그 생성자를 요구하면 실패합니다. 그래서 이 편의 도표는 fmapL을 집합 모형의 함수로 읽습니다.

unfoldr의 도표

종단 쌍대대수 자리에는 리스트 [a]를 놓습니다. 이 도표는 완전히 정의된 유한 리스트와 무한 리스트를 다루는 집합 모형으로 읽습니다. 구조 사상은 리스트에서 한 층을 여는 함수 out입니다. 이 이름은 이 편의 설명용입니다.

out :: [a] -> Maybe (a, [a])
out []       = Nothing
out (x : xs) = Just (x, xs)

그러면 앞 편의 아나모피즘 도표가 다음과 같이 됩니다. 여기서 h = unfoldr step입니다.

 b ────────── h = unfoldr step ──────────→ [a]
 │                                          │
 │ step                                     │ out
 ↓                                          ↓
Maybe (a, b) ─────── fmapL h ─────────→ Maybe (a, [a])

교환 조건 out . h = fmapL h . step을 갈래별로 읽으면 h가 정해집니다. step b = Nothing이면 아래 경로의 결과가 Nothing이므로 out (h b) = Nothing, 곧 h b = []입니다. step b = Just (x, b')이면 아래 경로의 결과가 Just (x, h b')이므로 h b = x : h b'입니다. 이 두 등식이 Haskell 2010 보고서에 있는 unfoldr의 정의입니다 (Haskell 2010의 Data.List). 앞 편에서 교환 조건으로부터 Fix . fmap m . f를 얻은 것과 같은 계산입니다. 다른 점은 Fix와 unFix 대신 리스트 생성자와 out을 쓴다는 것뿐입니다.

예로 씨앗을 하나씩 줄이다가 0에서 멈추는 쌍대대수를 둡니다.

countdown :: Integer -> Maybe (Integer, Integer)
countdown n = if n == 0 then Nothing else Just (n, n - 1)
씨앗 countdown의 결과
3 Just (3, 2)
2 Just (2, 1)
1 Just (1, 0)
0 Nothing

따라서 unfoldr countdown 3 = 3 : 2 : 1 : [] = [3,2,1]입니다. 씨앗 3에서 도표의 두 경로를 따라가 봅니다. 아래 경로에서 countdown 3 = Just (3, 2)이고, fmapL h는 다음 씨앗 2만 h 2 = [2,1]로 바꾸어 Just (3, [2,1])을 만듭니다. 위 경로에서는 h 3 = [3,2,1]이고 out [3,2,1] = Just (3, [2,1])입니다. 두 결과가 같습니다. 중간값 Just (3, 2)의 2는 아직 펼치지 않은 꼬리의 씨앗이고, Just (3, [2,1])의 [2,1]은 그 씨앗을 펼친 결과입니다.

Nothing은 끝낼 수단입니다

원문은 “The value of Nothing will terminate the generation of the list”라고 말합니다. 이 문장은 step이 Nothing을 돌려줄 때 무엇이 일어나는지 말합니다. 그런 때가 반드시 온다는 뜻은 아닙니다. Maybe는 한 층에 끝을 표현할 수단을 주고, 실제로 끝나는지는 step과 첫 씨앗이 정합니다.

같은 countdown에 씨앗 −1을 주면 다음 씨앗은 −2, −3, …이고 0에 닿지 않습니다. 그래서 unfoldr countdown (-1)은 무한 리스트입니다. 이 경우에도 take 2 (unfoldr countdown (-1)) = [-1,-2]처럼 관찰한 만큼은 얻습니다. 앞 편의 스트림과 같은 이유입니다. 이 예에서 타입을 Integer로 둔 이유는 앞 편의 era와 같습니다. 고정 폭 Int에서는 값이 범위를 벗어날 때의 동작을 따로 따져야 합니다. 일반적으로 결과가 무한 리스트가 되는 조건은, 도달하는 모든 씨앗에서 step이 Just (x, 다음 씨앗)을 내놓는 것입니다. 예를 들어 \n -> Just (n, n + 1)은 앞 편의 nat과 같은 무한 리스트를 만듭니다. Nothing을 돌려준 적이 없다는 것만으로는 부족합니다. step True = Just (1, False)이고 step False = undefined이면, 첫 원소 1은 읽히지만 다음 리스트 생성자를 요구할 때 계산이 실패합니다.

이 차이는 앞 편의 최소·최대 고정점과 연결됩니다. 리스트 함자의 종단 쌍대대수는 유한 리스트와 무한 리스트를 모두 담았습니다. unfoldr의 결과 타입 [a]에도 두 종류가 모두 들어 있습니다. 원문이 말하는 ‘유한 리스트를 만든다’는 것은 그중 유한한 쪽에 도달할 수 있게 되었다는 뜻입니다.

렌즈: 전체 값 a와 초점 s

두 번째 예는 렌즈입니다. 렌즈는 큰 값의 한 부분을 읽고 바꾸는 두 함수의 묶음입니다. 원문은 게터(getter)와 세터(setter)를 다음과 같이 적습니다.

set :: a -> s -> a
get :: a -> s

원문의 설명에 따르면 a는 보통 곱 타입이고, 그 안에 타입 s인 필드가 있습니다. 이 편에서는 이 필드를 초점이라고 부릅니다. 이름과 점수의 쌍 (String, Integer)에서 둘째 성분을 초점으로 삼는 예를 둡니다.

get :: (String, Integer) -> Integer
get (name, x) = x

set :: (String, Integer) -> Integer -> (String, Integer)
set (name, x) v = (name, v)

r = ("A", 3)이면 get r = 3이고 set r 8 = ("A", 8)입니다. set의 첫 인자가 전체 값이라는 점에 주의하십시오. set r은 새 초점값을 받아 새 전체 값을 돌려주는 함수 Integer -> (String, Integer)입니다. 그래서 같은 r에서 get r과 set r을 함께 만들 수 있습니다.

a -> (s, s -> a)
r ↦ (get r, set r)
("A", 3) ↦ (3, \v -> ("A", v))

원문은 이 쌍을 다음 함자의 값으로 다시 씁니다.

data Store s a = Store (s -> a) s

Store는 같은 두 성분을 순서만 바꾸어 담습니다. 그러면 렌즈 하나는 쌍대대수 하나입니다. 원문의 a -> Store s a는 일반적인 렌즈의 모양입니다. 앞의 예에서는 a = (String, Integer)이고 s = Integer이므로, 실행할 정의는 다음과 같습니다.

lens :: (String, Integer) -> Store Integer (String, Integer)
lens r = Store (set r) (get r)

원문의 문장 “A lens is a coalgebra for this functor with the carrier type a”에서 운반체는 초점 타입 s가 아니라 전체 값의 타입 a입니다. 함자 Store s의 fmap은 마지막 매개변수 a에 작용하므로, 저장된 함수의 결과에만 작용합니다. 이 fmap 정의는 저자의 후속 장 「Algebras for Monads」의 「Lenses」 절에 나옵니다 (저자의 후속 장).

instance Functor (Store s) where
  fmap h (Store f x) = Store (h . f) x

지수 a^s: 다음 상태가 여러 개인 한 층

원문은 Store가 합과 곱만으로 만든 함자가 아니며 지수 a^s를 포함한다고 말합니다. 지수는 함수 타입 s -> a입니다. 이 이름은 개수에서 왔습니다. 아래의 셈은 집합 모형에서 전함수(total function)를 세는 것입니다. Haskell 타입에는 ⊥가 있으므로, True와 False에서 같은 결과를 내는 두 함수도 undefined에서는 다를 수 있습니다. 집합 모형에서 s의 값이 k개이고 a의 값이 n개이면, s -> a인 함수는 n^k개입니다. 예를 들어 Bool -> a인 함수는 True와 False에 줄 값 두 개로 정해지므로 (a, a)와 대응합니다. s가 이처럼 유한하면 지수를 곱으로 풀 수 있습니다. 그러나 s가 Integer처럼 무한하면 a를 유한 번 곱하고 더해서는 이 함수 공간을 쓸 수 없습니다. 그래서 일반적인 s에서 Store s는 리스트나 스트림의 함자와 다른 종류입니다.

이 차이는 쌍대대수로 읽을 때 드러납니다. 지금까지 본 한 층을 비교합니다.

함자 관찰값 다음 상태
StreamF e 원소 하나 언제나 하나
Maybe (a, -) 원소 하나 또는 없음 없거나 하나
Store s 현재 초점 get r 새 초점값 v마다 하나, 곧 set r v

렌즈의 씨앗은 전체 값 r입니다. 한 층에서 관찰하는 것은 현재 초점이고, 다음 상태는 써 넣을 값을 고를 때마다 정해집니다. 앞 편의 전이 시스템으로 말하면, s는 관찰값이면서 다음 전이를 고르는 입력이기도 합니다.

lens와 ana lens의 도표

원문이 정의한 것은 한 걸음입니다.

     a ──────────── lens ────────────→ Store s a
("A", 3) ─────────────────────────→ Store (\v -> ("A", v)) 3

여기에 앞 편과 같은 방식으로 아나모피즘을 붙일 수 있습니다. 이것은 원문에 없는 설명용 확장입니다. T = Fix (Store s)로 두고 h = ana lens라고 하면 도표는 다음과 같습니다.

 a ─────────── h = ana lens ───────────→ T = Fix (Store s)
 │                                        │
 │ lens                                   │ unFix
 ↓                                        ↓
Store s a ────────── fmap h ─────────→ Store s T

r = ("A", 3)에서 두 경로를 따라가 봅니다. 아래 경로에서 lens r = Store (set r) 3이고, fmap h는 이 값을 Store (h . set r) 3으로 바꿉니다. 현재 초점 3은 그대로이고, 저장된 갱신 함수만 바뀝니다. 위 경로에서는 ana의 정의에 따라 h r = Fix (Store (h . set r) 3)이므로, unFix (h r)도 같은 값입니다. 이 값의 갱신 함수에 8을 주면 h (set r 8) = h ("A", 8)을 얻고, 그 바깥 층의 초점은 8입니다.

따라서 T의 값 하나는 ‘지금 읽으면 무엇이 보이고, 어떤 값을 쓴 뒤에는 무엇이 보이는가’를 끝없이 담은 나무입니다. 각 마디에서 s의 값마다 가지가 하나씩 나옵니다. 지연 평가 때문에 실제로 만들어지는 것은 관찰한 경로뿐입니다. 이 예에서 set r 8은 한 번의 쓰기로 계산되고, ana lens는 그 쓰기 뒤에 무엇을 읽을지 보여 줍니다. 이 도표는 원문의 쌍대대수가 앞 편의 펼치기 도표에 그대로 들어간다는 것을 보이려고 그렸습니다.

잘 동작하는 렌즈와 comonad 구조

원문은 이 절을 두 문장으로 마칩니다. Store s는 앞 장에서 본 코모나드(comonad)이고, 잘 동작하는(well-behaved) 렌즈는 그 코모나드 구조와 맞는 쌍대대수에 대응한다는 것입니다. 증명은 다음 장으로 미룹니다 (저자의 후속 장).

먼저 ‘잘 동작한다’의 뜻을 앞의 예로 확인합니다. 렌즈의 세 법칙은 다음과 같습니다 (렌즈의 대수적·쌍대대수적 기술). 아래 표와 반례는 완전히 정의된 입력에서 비교합니다.

법칙 식 r = ("A", 3)에서
읽은 값을 다시 쓰면 그대로입니다 set r (get r) = r set r 3 = ("A", 3)
쓴 값을 읽으면 그 값입니다 get (set r v) = v get ("A", 8) = 8
두 번 쓰면 마지막 쓰기만 남습니다 set (set r v) w = set r w set ("A", 8) 9 = ("A", 9)

용어는 문헌마다 다릅니다. Gibbons와 Johnson은 앞의 두 법칙을 만족하는 렌즈를 well-behaved라고 부르고, 셋째 법칙까지 만족하는 렌즈를 very well-behaved라고 부릅니다. 세 법칙을 모두 만족하는 렌즈를 well-behaved라고 부르는 것은 Milewski의 표현입니다.

타입은 이 법칙들을 강제하지 않습니다. 다음은 설명을 위해 만든 반례입니다. 쓸 때마다 이름에 !를 붙이는 세터 set' (name, x) v = (name ++ "!", v)도 이 예의 세터 타입 (String, Integer) -> Integer -> (String, Integer)으로 쓸 수 있습니다. 완전히 정의된 입력에서는 쓴 값을 읽으면 그 값이므로 둘째 법칙이 성립합니다. 그러나 set' r 3 = ("A!", 3)이므로 첫째 법칙이 깨집니다. 또 두 번 쓰면 ("A!!", 9)이고 한 번 쓰면 ("A!", 9)이므로 셋째 법칙도 깨집니다. 첫 편에서 뺄셈이 이항 연산 자리에 타입으로는 맞지만 결합법칙을 따로 확인해야 했던 것과 같은 상황입니다.

원문의 주장은 세 법칙을 만족하는 렌즈가 Store s의 코모나드 구조와 양립하는 쌍대대수라는 것입니다. 저자는 그 대응을 다음 장에서 보입니다.

원문의 본문은 이 편에서 끝납니다. 대수에서는 자식 자리에 이미 계산한 결과가 들어 있었고, 구조 사상은 그 결과를 합쳤습니다. 쌍대대수에서는 자식 자리에 다음 상태가 들어 있었고, 구조 사상은 그 상태를 만들었습니다. unfoldr의 쌍대대수는 끝낼지를 골랐고, 렌즈는 쓸 값마다 다음 상태를 정했습니다. 원문의 연습문제는 이 두 방향을 직접 써 보게 합니다. 다음 편의 질문은 두 가지입니다. 다항식과 행렬을 RingF의 운반체로 삼으면 각 생성자를 어떻게 해석해야 할까요? 그리고 제곱수와 처음 n개의 소수를 펼치려면 씨앗에 무엇을 담아야 할까요?
