앞 편은 원문 본문의 마지막 문단을 읽고 두 질문을 남겼습니다. 다항식이나 행렬을 RingF의 운반체로 삼으면 생성자 다섯 개를 어떻게 해석해야 할까요? 제곱수와 처음 n개의 소수를 펼치려면 씨앗에 무엇을 담아야 할까요? 원문의 「Challenges」 절에 있는 다섯 연습문제가 바로 이 질문입니다 (원문의 연습문제). 앞의 세 문제는 대수(algebra)의 운반체(carrier)를 바꿉니다. 뒤의 두 문제는 쌍대대수(coalgebra)의 씨앗(seed)을 설계합니다. 아래 풀이는 원문에 없는 설명용 구성입니다. 계산은 각 단계를 손으로 따라가며 보입니다.

연습문제 1~3: 운반체만 바꾸는 대수

원문의 대수는 함자 한 층을 결과 하나로 접는 함수였습니다.

type Algebra f a = f a -> a

data RingF a = RZero | ROne | RAdd a a | RMul a a | RNeg a
  deriving Functor

뒤에서 쓰는 cata는 fmap을 부르므로 RingF에는 Functor 인스턴스가 필요합니다. 그래서 선언에 deriving Functor를 붙입니다. Haskell 2010 설정에서는 파일 맨 위에 {-# LANGUAGE DeriveFunctor #-}를 두어 이 확장을 켭니다 (GHC의 DeriveFunctor). 뒤에 나오는 StreamF의 deriving Functor도 같습니다.

첫 편에서 본 evalZ :: Algebra RingF Integer는 운반체가 정수입니다. 그래서 RAdd m n을 정수 덧셈 m + n으로, RNeg n을 -n으로 해석했습니다. 첫 연습문제는 “Implement the evaluation function for a ring of polynomials of one variable”이라고 말합니다. evalZ와 나란히 읽으면, 이 문장은 운반체가 다항식인 대수 RingF Poly -> Poly를 쓰라는 뜻으로 해석됩니다. 다항식의 x에 수를 대입하는 함수와는 다른 함수입니다. 할 일은 생성자 다섯 개에 다항식의 0, 1, 덧셈, 곱셈, 부호 반전을 하나씩 대응시키는 것입니다. 연습문제 2와 3도 운반체만 바꾸어 같은 일을 합니다.

한 변수 다항식: 목록의 위치가 차수입니다

원문은 다항식을 x의 거듭제곱 앞에 붙은 계수(coefficient)의 목록으로 나타내라고 합니다. 0차부터 적은 4x² − 1의 표현으로는 [-1, 0, 4]를 듭니다. 목록의 i번째 자리(0부터 셉니다)가 xⁱ의 계수입니다. 그러면 0은 [], 1은 [1], x는 [0, 1]입니다.

덧셈은 같은 자리끼리 더하고, 한쪽이 먼저 끝나면 다른 쪽의 나머지를 그대로 붙입니다. 곱셈은 등식 하나로 정의합니다. p의 맨 앞 계수를 a, 나머지를 p′라고 하면 p = a + x·p′이므로 다음이 성립합니다.

p · q = a·q + x·(p′ · q)

목록 표현에서 x를 곱하는 일은 모든 계수를 한 자리 뒤로 미는 일, 곧 맨 앞에 0을 붙이는 일입니다.

type Poly = [Integer]

addP :: Poly -> Poly -> Poly
addP [] q = q
addP p [] = p
addP (a : as) (b : bs) = (a + b) : addP as bs

mulP :: Poly -> Poly -> Poly
mulP [] _ = []
mulP (a : as) q = addP (map (a *) q) (0 : mulP as q)

원문의 예를 거꾸로 확인합니다. 4x² − 1 = (2x − 1)(2x + 1)이므로 [-1, 2]와 [1, 2]를 곱합니다.

mulP [-1,2] [1,2]
= addP [-1,-2] (0 : mulP [2] [1,2])
= addP [-1,-2] (0 : addP [2,4] (0 : mulP [] [1,2]))
= addP [-1,-2] (0 : addP [2,4] [0])
= addP [-1,-2] [0,2,4]
= [-1,0,4]

결과가 정해지는 곳은 일차항입니다. 둘째 줄의 -2는 (−1)·2x에서 왔고, 다섯째 줄의 2는 2x·1에서 왔습니다. 두 기여를 더하면 (-1)×2 + 2×1 = 0입니다. 이 0은 지울 수 없습니다. 지우면 [-1, 4], 곧 4x − 1이 됩니다. 이 표현에서는 자리가 차수를 나타내기 때문입니다.

지워도 되는 0은 맨 뒤의 0뿐입니다. 식 RAdd ROne (RNeg ROne)을 한 층씩 평가하면 [1]과 [-1]을 더해 [0]을 얻습니다. 그런데 RZero는 []를 줍니다. 두 목록은 같은 다항식 0이지만, 리스트의 ==는 둘이 다르다고 판단합니다. mulP [1,1] []도 [0,0]을 냅니다. 그래서 맨 뒤의 0을 없애는 정규화(normalization)를 덧셈과 곱셈 뒤에 둡니다.

norm :: Poly -> Poly
norm = reverse . dropWhile (== 0) . reverse

evalP :: Algebra RingF Poly
evalP RZero      = []
evalP ROne       = [1]
evalP (RAdd p q) = norm (addP p q)
evalP (RMul p q) = norm (mulP p q)
evalP (RNeg p)   = map negate p

norm [0,0] = []이고 norm [-1,0,4] = [-1,0,4]입니다. 이 대수의 운반체는 맨 뒤에 0이 없는 유한 계수 목록이고, 영다항식은 []입니다. 밖에서 만든 목록은 norm을 거친 뒤에 피연산자로 넣습니다. 이 조건에서는 RNeg에 norm이 필요 없습니다. 0이 아닌 계수는 부호를 바꾸어도 0이 아니므로, 맨 뒤의 계수가 0이 아닌 목록은 부호를 바꾸어도 그대로 정규형입니다. 조건을 지키지 않으면 evalP (RNeg [0])은 [0]을 돌려주고, 이 값은 RZero의 결과 []와 리스트 동등성에서 다릅니다.

닫힌 식에는 x를 쓸 수 없습니다

evalP가 다항식의 대수라는 것은 한 층에서 가장 잘 보입니다. evalP (RMul [-1,2] [1,2]) = [-1,0,4]에서 두 피연산자는 이미 계산된 다항식입니다. 그런데 Fix RingF의 잎은 RZero와 ROne뿐입니다. 따라서 cata evalP가 받는 닫힌 식은 정수 상수만 만듭니다. 둘째 편의 식 (1+1)×(−1)을 cata evalP로 접으면 [1], [2], [-1]을 거쳐 [-2]가 됩니다. 이것은 evalZ의 결과 −2를 상수 다항식으로 적은 것입니다.

식 트리 안에 x를 쓰려면 함자에 변수 생성자, 예를 들어 RX를 더하고 RX를 [0,1]로 해석해야 합니다. 이것은 원문의 RingF를 넘어서는 확장입니다. 연습문제가 요구하는 것은 한 층의 해석이므로 원래의 RingF로 충분합니다.

여러 변수: 지수 벡터를 열쇠로 저장합니다

둘째 문제는 x²y − 3y³z처럼 서로 독립인 변수가 여럿인 다항식으로 일반화하라고 합니다. 변수가 여럿이어도 1, x, y, x², xy, y², …처럼 단항식(monomial)의 순서를 정하면 목록의 위치 하나로 각 항을 식별할 수 있습니다. 그러나 한 변수에서처럼 위치를 차수로 읽는 방식은 통하지 않습니다. x와 y는 총차수가 모두 1이므로 총차수만으로는 두 항을 구별하지 못합니다. 그래서 변수의 순서를 (x, y, z)로 고정하고, 단항식의 지수 벡터를 열쇠로 삼아 계수와 짝을 짓습니다. 지수 벡터에서는 각 변수의 지수를 직접 읽고, 곱셈에서 바로 더할 수 있습니다. SageMath도 여러 변수 다항식의 한 내부 표현으로 지수 튜플에서 계수로 가는 사전을 씁니다 (SageMath의 PolyDict).

x²y − 3y³z  =  { [2,1,0] ↦ 1, [0,3,1] ↦ −3 }

이 표현은 xy와 yx를 같은 열쇠 [1,1,0]으로 적습니다. 곧 변수끼리는 곱셈의 순서를 바꿀 수 있다고 가정합니다. 원문의 ‘independent variables’를 이런 가환 변수로 읽은 것입니다.

지수에는 음수가 없고, 곱셈에서는 지수를 더하기만 합니다. 그래서 지수의 타입으로 고정 상한이 없는 Natural을 씁니다 (Numeric.Natural). 고정 폭 Int를 쓰면 길이가 맞는 두 단항식을 곱해도 덧셈이 범위를 넘어 잘못된 지수가 생길 수 있습니다.

import qualified Data.Map.Strict as M
import Numeric.Natural (Natural)

nVars :: Int
nVars = 3                        -- x, y, z

type Mono  = [Natural]           -- 변수 순서대로 놓은 지수
type MPoly = M.Map Mono Integer

addM :: MPoly -> MPoly -> MPoly
addM p q = M.filter (/= 0) (M.unionWith (+) p q)

mulM :: MPoly -> MPoly -> MPoly
mulM p q = M.filter (/= 0) (M.fromListWith (+)
  [ (zipWith (+) e f, a * b) | (e, a) <- M.toList p, (f, b) <- M.toList q ])

evalM :: Algebra RingF MPoly
evalM RZero      = M.empty
evalM ROne       = M.singleton (replicate nVars 0) 1
evalM (RAdd p q) = addM p q
evalM (RMul p q) = mulM p q
evalM (RNeg p)   = M.map negate p

곱셈의 원리는 한 변수일 때와 같습니다. 두 단항식을 곱하면 계수는 곱하고 지수는 변수마다 더합니다. 같은 단항식이 여러 번 나오면 fromListWith (+)가 그 계수를 모읍니다 (Data.Map.Strict 문서). 한 변수에서 차수의 합이 같은 항을 모은 일과 같습니다. 예를 들어 x²y − 3y³z에 x = {[1,0,0] ↦ 1}을 곱하면 각 지수 벡터에 [1,0,0]이 더해집니다. 결과는 {[3,1,0] ↦ 1, [1,3,1] ↦ −3}, 곧 x³y − 3xy³z입니다.

상쇄가 일어나는 예는 (x + y)(x − y)입니다. 네 쌍의 곱은 다음과 같습니다.

곱 지수 벡터 계수
x · x [2,0,0] 1
x · (−y) [1,1,0] −1
y · x [1,1,0] 1
y · (−y) [0,2,0] −1

fromListWith (+)가 [1,1,0]의 계수를 모아 0을 만들고, M.filter (/= 0)이 그 항목을 지웁니다. 결과는 {[2,0,0] ↦ 1, [0,2,0] ↦ −1}, 곧 x² − y²입니다. 한 변수 표현에서는 가운데 0을 지울 수 없었습니다. 여기서는 지워야 합니다. 이 표현에서는 지수가 자리가 아니라 열쇠에 있기 때문입니다. 0인 항목을 모두 지우면 다항식 0의 표현은 빈 사전 하나뿐이므로 따로 norm을 둘 필요가 없습니다. 밖에서 직접 넣는 사전에도 계수가 0인 항목이 없어야 합니다. 그래야 M.map negate가 이 정규형을 보존합니다.

변수가 d개이면 nVars를 d로 두고 모든 열쇠의 길이를 d로 고정합니다. 그러면 ROne의 열쇠는 replicate d 0입니다. 이 코드는 이 길이 조건을 가정합니다. zipWith는 길이가 다른 두 목록을 짧은 쪽에 맞추어 자르기 때문입니다.

2×2 행렬: 곱셈의 순서가 결과를 바꿉니다

셋째 문제는 운반체를 2×2 정수 행렬로 바꿉니다. 행렬 ((a, b), (c, d))를 M2 a b c d로 적습니다. 0은 영행렬이고 1은 대각선 성분만 1인 단위행렬입니다. 덧셈과 부호 반전은 성분마다 합니다. 곱 AB의 (i, j) 성분은 A의 i행과 B의 j열에서 같은 위치의 성분끼리 곱해 더한 값입니다.

data M2 = M2 Integer Integer Integer Integer   -- 행 우선: a b / c d

evalM2 :: Algebra RingF M2
evalM2 RZero = M2 0 0 0 0
evalM2 ROne  = M2 1 0 0 1
evalM2 (RAdd (M2 a b c d) (M2 e f g h)) = M2 (a + e) (b + f) (c + g) (d + h)
evalM2 (RMul (M2 a b c d) (M2 e f g h)) =
  M2 (a * e + b * g) (a * f + b * h) (c * e + d * g) (c * f + d * h)
evalM2 (RNeg (M2 a b c d)) = M2 (negate a) (negate b) (negate c) (negate d)

정수와 다항식의 곱셈은 순서를 바꾸어도 결과가 같았습니다. 행렬에서는 다릅니다. 오른쪽 위 성분만 1인 A = M2 0 1 0 0과 왼쪽 아래 성분만 1인 B = M2 0 0 1 0을 곱합니다.

AB: 왼쪽 위 = 0·0 + 1·1 = 1, 나머지 세 성분 = 0     →  M2 1 0 0 0
BA: 오른쪽 아래 = 1·1 + 0·0 = 1, 나머지 세 성분 = 0  →  M2 0 0 0 1

따라서 RMul의 첫 필드는 왼쪽 인수이고 둘째 필드는 오른쪽 인수입니다. 두 필드를 바꾸어 곱하는 정의도 같은 타입을 가지고 환의 법칙도 지킵니다. 그러나 그 정의는 RMul a b를 AB가 아니라 BA로 해석합니다. 어느 해석인지는 타입이 아니라 정의를 쓰는 쪽이 정합니다.

여기서도 닫힌 Fix RingF 식만으로는 이 차이가 보이지 않습니다. 0, 1, 덧셈, 곱셈, 부호 반전으로 만든 행렬은 모두 n·I 꼴의 스칼라 행렬입니다. 스칼라 행렬은 어떤 행렬과 곱해도 순서를 바꿀 수 있습니다. 순서의 차이는 앞의 예처럼 피연산자를 한 층에 직접 줄 때 보입니다.

연습문제 4: 제곱수의 씨앗은 k, 관찰값은 k²입니다

이제 화살표의 방향이 바뀝니다. 원문의 쌍대대수와 아나모피즘(anamorphism)의 정의를 다시 적습니다.

type Coalgebra f a = a -> f a

data StreamF e a = StreamF e a deriving Functor

ana :: Functor f => Coalgebra f a -> a -> Fix f
ana coalg = Fix . fmap (ana coalg) . coalg

넷째 문제는 자연수의 제곱을 차례로 내는 쌍대대수를 요구합니다. 대수에서는 운반체를 정했고, 쌍대대수에서는 씨앗을 정합니다. 가장 직접적인 씨앗은 현재 자연수 k입니다. 한 층에서 k²을 관찰값으로 내고 k + 1을 다음 씨앗으로 남깁니다.

squares :: Coalgebra (StreamF Integer) Integer
squares k = StreamF (k * k) (k + 1)

자연수는 앞 편의 페아노 자연수처럼 0부터 셉니다. ana squares 0은 Fix (StreamF Integer) 값이므로 앞 편의 toListC로 리스트로 바꾸어 관찰합니다.

씨앗 squares의 결과
0 StreamF 0 1
1 StreamF 1 2
2 StreamF 4 3
3 StreamF 9 4

따라서 take 4 (toListC (ana squares 0)) = [0,1,4,9]입니다. 결과가 무한하므로 관찰하는 쪽이 take로 멈춥니다. 결과를 처음부터 리스트로 받으려면 언제나 Just를 내는 쌍대대수를 unfoldr에 주어도 됩니다. unfoldr는 Data.List에 있으므로 먼저 가져옵니다 (Haskell 2010의 Data.List).

import Data.List (unfoldr)

unfoldr (\k -> Just (k * k, k + 1)) 0은 같은 무한 리스트입니다.

씨앗이 관찰값과 같을 필요는 없습니다. 현재 제곱 k²만 씨앗으로 두어도 다음 제곱을 얻을 수는 있습니다. 예를 들어 제곱들을 작은 순서로 열거해 9보다 큰 첫 값을 고르면 제곱근을 계산하지 않고 16을 얻습니다. 씨앗을 (k, k²)으로 넓히면 k가 이미 씨앗에 있습니다. 그래서 (k + 1)² = k² + 2k + 1, 곧 s + 2 * k + 1로 다음 제곱을 바로 계산합니다.

squares' :: Coalgebra (StreamF Integer) (Integer, Integer)
squares' (k, s) = StreamF s (k + 1, s + 2 * k + 1)

(0,0)에서 시작하면 씨앗은 (1,1), (2,4), (3,9)로 바뀌고 관찰값은 0, 1, 4, 9입니다. 다음 문제에서도 씨앗을 쌍으로 넓힙니다.

연습문제 5: 처음 n개의 소수는 남은 개수를 씨앗에 담습니다

앞 편의 소수 스트림 ana era [2..]에는 끝내는 갈래가 없었습니다. 그래서 처음 몇 개만 원할 때는 관찰하는 쪽이 take로 멈춰야 했습니다. 다섯째 문제는 unfoldr로 처음 n개의 소수를 만들라고 합니다. 이번에는 쌍대대수가 스스로 멈추어야 합니다. 멈출 때를 알려면 앞으로 몇 개를 더 낼지 알아야 하므로, 남은 개수를 후보 목록과 함께 씨앗에 담습니다. 원문의 era는 [Int]에 대해 정의되어 있으므로, 앞 편처럼 같은 정의를 Integer에 대해 씁니다.

era' :: Coalgebra (StreamF Integer) [Integer]
era' (p : ns) = StreamF p (filter (notdiv p) ns)
  where notdiv p n = n `mod` p /= 0

firstPrimes :: Int -> [Integer]
firstPrimes n = unfoldr step (n, [2 ..])
  where
    step (k, ns)
      | k <= 0    = Nothing
      | otherwise = case era' ns of
          StreamF p rest -> Just (p, (k - 1, rest))

step은 개수를 먼저 봅니다. 남은 개수가 0이면 후보 목록을 열지 않고 Nothing을 냅니다. 양수이면 era'가 준 한 층 StreamF p rest를 Maybe 쌍으로 옮깁니다. 관찰값 p는 쌍의 첫 성분이 되고, 다음 씨앗은 개수를 하나 줄인 (k − 1, rest)가 됩니다 (Haskell 2010의 unfoldr). n = 3에서 씨앗을 따라갑니다.

씨앗 step의 결과
(3, [2,3,4,5,6,7,…]) Just (2, (2, [3,5,7,9,11,…]))
(2, [3,5,7,9,11,…]) Just (3, (1, [5,7,11,13,17,…]))
(1, [5,7,11,13,17,…]) Just (5, (0, [7,11,13,17,19,…]))
(0, …) Nothing

따라서 firstPrimes 3 = [2,3,5]이고 firstPrimes 0 = []입니다. 음수 n도 k <= 0 갈래에서 []가 됩니다.

양수인 k에서 era' (p : ns)의 패턴이 언제나 맞는 이유는 후보 목록의 내용에 있습니다. 각 단계의 후보 목록은 지금까지 낸 소수보다 큰 수 중에서 그 소수들의 배수를 뺀 것입니다. 더 큰 소수는 더 작은 소수로 나누어지지 않으므로 하나도 제거되지 않습니다. 소수는 무한히 많으므로 후보 목록은 비지 않습니다. 또 남은 첫 후보 m은 소수입니다. m이 합성수라면 m보다 작은 소인수 q가 있습니다. q가 이미 낸 소수 중 하나라면 m은 그 단계에서 제거되었어야 합니다. 그렇지 않다면 q 자신이 m보다 앞에 남아 있었어야 합니다. 그래서 개수가 남아 있는 동안에는 era'를 계속 적용할 수 있고, 개수가 0이 되면 후보를 열지 않고 끝납니다.

이 예에서 앞 편의 문장이 구체적인 모양을 얻습니다. Maybe는 끝을 표현할 수단이고, 실제로 끝나는지는 step과 첫 씨앗이 정한다는 문장입니다. 후보 목록은 앞에서 본 대로 비지 않으므로 끝을 정하지 않습니다. 끝을 정하는 것은 씨앗에 넣은 개수입니다. 결과는 take n (toListC (ana era' [2 ..]))와 같습니다. 다른 점은 멈춤의 위치입니다. take는 무한한 결과의 앞부분만 읽습니다. firstPrimes에서는 쌍대대수가 Nothing으로 리스트를 끝내므로 처음부터 유한한 리스트가 만들어집니다.

다시 두 타입으로, 그리고 원문의 끝

다섯 문제를 원문의 두 타입으로 다시 읽습니다.

type Algebra   f a = f a -> a
type Coalgebra f a = a -> f a

연습문제 1~3에서 RingF Poly, RingF MPoly, RingF M2의 자식 자리에는 이미 계산된 다항식과 행렬이 있었습니다. 대수는 그 결과들을 결합했습니다. 가운데 계수를 상쇄하고, 같은 지수 벡터의 계수를 모으고, 행과 열을 곱했습니다. 연습문제 4~5에서 StreamF Integer Integer와 Maybe (Integer, (Int, [Integer]))의 자식 자리에는 다음 씨앗이 있었습니다. 쌍대대수는 그 씨앗을 만들었습니다. 다음 자연수를 정하고, 남은 개수를 줄이고, 후보를 걸렀습니다. 화살표가 f a에서 나가는지, f a로 들어가는지가 이 차이를 정합니다.
