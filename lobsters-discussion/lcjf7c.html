What is still exciting in tech? · ploum · 2026-09-18 · Lobsters source — A comment on a lobste.rs post about the tech culture stagnating made me think.

20-15 or even 10 years ago, tech was really exciting. Sure, monopolies were bad, I was fighting them, but tech by itself was very interesting. New versions of software were expected, we were skimming through changelogs to find novelties, installing beta or alpha versions of totally unknown projects. And I had lived that excitement since the 90’s.

When you think about it, today feels really bleak in comparison:

  • Changelogs of commercial projects now all have that pseudo-humorous tone to tell you that "they improved performance and fixed bugs"
  • The best smartphone I ever had is now 10 years old (and was not an expensive one, see https://ploum.net/2026-09-02-i_dont_have_a_smartphone.html )
  • Around me, at least 3 totally unrelated people left a decade-long career in tech to do woodworking. And they are way happier.
  • My main interest in looking at changelogs is now to see how the projects I use will be enshitified with AI integration
  • Even my beloved Free Software stack is now heavily tainted by slop
  • Lot of people that could have been doing very cool thing (or were doing very cool things) are now outspoken fascist ( see https://git.sr.ht/~rabbits/fashware/tree/main/item/README.md or https://drewdevault.com/weird-guys/ )
  • Even if you are interested by AI, the ecological consequences and the way it is used are simply awful.

All of this makes me wonder: am I just a grumpy already old man? Am I missing something? If so, what?

So I would like to ask all lobste.rs: what do you find really exciting in tech today? What are you waiting with impatience? Which project are you following closely? What do you expect from them? What do you hope to see in the next few months or years?

simonw · 2026-09-18 · comment — I'm excited about WebAssembly. It's really coming together now.

  • The browser implementations are about a decade old, and extremely robust and well tested.
  • There are a bunch of separate implementations, which is crucial for a healthy standard.
  • Significant projects like Python and SQLite treat it as one of their supported deployment targets.
  • Most of the time if I want to use a big piece of C software in a browser - something like ffmpeg - there's a packaged WASM library I can use for that already.
  • The non-browser implementations like wasmtime and wasmer are maturing nicely.
  • WASI is beginning to take off.

I think WASM has a real chance at delivering a secure, robust, cross-platform sandbox. We really need one of those right now - why would I ever want to run untrusted code outside of a robust sandbox in 2026?

Loup-Vaillant · 2026-09-18 · comment — Lobsters reply.

Now that questionable quality is everywhere, package management and curation of software becomes more important, IMO.

Curation, unquestionably yes. Package management though? Take for instance the issue of static vs dynamic linking, with respect to security:

  • Dynamic linking is better, because package maintainer can quickly apply a patch to a vulnerable library and instantly protect all programs that depends on it. Can't trust developers with this one, some of them are bound to lag on updates, and we want to protect our users.
  • Static linking is better, because developers can quickly apply a patch to a vulnerable library and instantly update their program without breaking anything. Can't trust distros with this one, some of them are bound to lag on updates, and we want to protect our users.

What I'd really like in the Linux space, is a stable foundation. Something sufficient to build programs on top, including graphical & interaction intensive ones, that does not break users. Similar to the Linux kernel, or the old Windows APIs (before they started to break stuff). Something minimal, I'm not asking for a GUI toolkit, or even a font renderer. Just enough of an API so I can build my own, and have it work forever (that may involve protocols for screen readers & the like).

Now I wouldn't mind a distro that encourages developers to use a specific set of dynamically linked dependencies. As long as they're crystal clear which have a stable ABI, and the non-stable ones aren't strictly necessary to build & deploy my program.

As a user though I love the official store front. Do keep pkg-mgr install awesome_software, automatic updates... I can't just trust some random dev on the internet after all.
