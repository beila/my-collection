Definitions, coverage, and retention

Instapaper usage: Unread and custom folders form the stacked area on the left axis. Archive is a separate line on the right axis and is excluded from the stack. Both axes use the same bookmark count scale. Folder sizes use the last complete observation in each interval; earlier missing breakdowns remain blank. Additions, folder moves, and deletions appear in a separate graph and sum observed changes within each interval. Manual and automated activity both count. Reordering and metadata edits are not moves. The first observation establishes a baseline and does not count existing bookmarks as additions. Changes that happen entirely between observations are unknown. Earlier totals and deleted bookmarks cannot be reconstructed.

Source check: one attempted acquisition and parse for a direct feed, rolling newsletter, reading-index source, or enabled Facebook profile, or one Readnext selection attempt when Smith needs articles. Inner retries are one check. A condition being evaluated without fetching or selecting articles is not a check.

New bookmarks & editions: unique bookmark IDs with confirmed delivery receipts. Replacement newsletter editions count as arrivals. Conversions of existing saved links have their own measure; refreshes, temporary verification copies, and moves are excluded. A 다읽기 page counts as one bookmark, even when it contains several articles.

Routed bookmarks: Readnext articles confirmed in Smith after population finishes, counted once per population. Series companions moved to Morpheus are excluded. These moves are separate from new arrivals. Earlier Readnext activity is not reconstructed.

Kindle digests: one document identity counts once across retries. “Built” requires a measured EPUB; confirmed sends include a retained prior delivery when available. A pending or uncertain send does not count as confirmed. History before instrumentation is partial; missing sizes and origins stay unknown. The source breakdown uses only articles actually included in the EPUB, even when building skips an article. “Repeated” means present in the previous confirmed digest, regardless of source.

Digest size: MiB is 1,048,576 bytes. Images include the cover; image bytes are uncompressed ZIP member sizes. Words are whitespace-separated text units in article chapters; headings exclude the navigation document. Build time excludes email delivery. Direct program additions require recorded delivery into Smith; conversions do not establish who added the original.

Image storage: the four bands count GitHub deployed images, new GitHub image backups excluded from Pages, legacy Backblaze images, and new Backblaze images. New means newly captured images outside the legacy inventory, not additions during a time interval. Each location counts distinct new objects once. Backblaze objects are partitioned between legacy and new images. GitHub backups contain image bytes only; manifest bytes and retained legacy backups are excluded from the new band. The complete deployment details retain total backup measurements. The stack counts stored copies across locations, so an image retained in GitHub and Backblaze contributes to both locations. Missing earlier breakdowns remain unknown.

Collection storage: deployment size is the uncompressed total of the staged website, including its measurement file. One point per successful deployment uses its build time in UTC. All recorded deployment, migration, and excluded-original measurements are retained. History follows the selected period; source, destination, and interval filters do not apply. Migration counts distinct, verified B2 objects; uploading an image does not remove its old Pages copy. Daily migration usage counts reserved requests and bytes, not account-wide Backblaze usage.

Historical additions: confirmed, dated feed-monitor records retained locally. They provide partial history, not an account-wide total. Checks and queue measurements begin when recording was installed; blank earlier periods mean unknown. Source cadence and destination associations for checks use the current catalog; delivered bookmark destinations are recorded at delivery.

External accesses: Instapaper uses the left axis and Facebook uses the right axis, with independent count scales on the same timeline. One count means one explicit Instapaper API or authenticated web request, Facebook browser page load, or HTTP fetch from Facebook and its media hosts. Each retry counts separately. Local caches and lock polling add no accesses. Completed accesses mean successful HTTP responses or browser loads without a network error; they do not prove that a page's content was usable. Implicit browser asset requests and scrolling requests are not measured. These global counts use the selected period and interval, independent of source and destination filters.

Successful agent CLI calls: one count per accepted Codex, Claude, or Kiro CLI completion through this automation's shared agent launcher. Failed, unavailable, and authentication-deferred fallbacks do not count. A direct Claude call requires a successful exit and a valid result envelope. Completion dates use UTC. These are CLI calls, not individual model requests, tool calls, or interactive sessions elsewhere. Earlier calls are not reconstructed from output files.

All recorded activity, Instapaper usage, digest, deployment, and daily queue history is retained. Detailed hourly queue observations are kept for 35 days. “All recorded time” includes available history; it does not imply coverage before recording began. The public snapshot updates with collection page deployments. All dates and chart buckets use UTC. No bookmark identities, text, repair notes, error messages, or credentials are exported.
